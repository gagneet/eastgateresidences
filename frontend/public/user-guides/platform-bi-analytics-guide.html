Platform Analytics Guide

This guide is for Super Admins — the StrataOS platform operators who oversee all strata companies and all buildings. Platform Analytics gives you visibility across the entire platform, not just a single company or building.

Access note: Platform Analytics is only visible to super admin accounts. Strata admins and strata managers see their own company's data only. If you believe you should have access and do not, contact your StrataOS system administrator.

Accessing Platform Analytics

  1. Log in with your super admin account.
  2. Go to Super Admin → Platform Analytics from the main navigation.
  3. The platform analytics dashboard loads, showing aggregate data across all strata companies and all buildings registered on the platform.

Monitoring All Buildings Across All Companies

The Platform Overview panel at the top of the page shows platform-wide metrics:

  • Total active buildings — all buildings currently live on the platform.
  • Total active owners and tenants — registered portal users across all buildings.
  • Platform-wide levy collection rate — the average across all buildings. Useful for benchmarking individual companies.
  • Total arrears (platform) — the aggregate outstanding levy balance across every building. This is a platform health indicator.
  • Compliance overdue count (platform) — how many compliance items are currently overdue across all buildings.

Building Health Ranking

The Building Health Ranking table lists every building on the platform with a composite health score. Buildings are ranked from best to worst. You can filter by:

  • Strata company (to compare performance across companies).
  • Health score range (for example, show only buildings scoring below 50).
  • State or territory.

Click any building row to open that building's detailed analytics view. You can also use the building switcher to enter any building's management interface directly.

Tip: The building health ranking is a useful tool for identifying which strata companies may need a support conversation. A company with many low-scoring buildings may be under-resourced or need platform training.

Feature Adoption Tracking

The Feature Adoption panel shows which platform features are being used, and by how many buildings:

  • Features that are enabled but rarely accessed — a signal that training or onboarding may be needed.
  • Features that are disabled for many buildings — useful for prioritising outreach to companies that are not yet using key capabilities.
  • Rollout percentage — for features that are being gradually enabled, the current percentage of buildings with access.

Data Freshness and ETL Health

StrataOS processes data from various sources to populate analytics dashboards. The Data Health panel shows:

  • Last refresh time — when the analytics data was last updated for each building or data source.
  • Stale data warnings — buildings whose analytics data has not refreshed within the expected window are flagged amber or red.
  • Processing errors — if a data pipeline has failed for a specific building, it appears here with an error description.

Triggering an ETL Refresh

If a building's data appears stale or incorrect, you can manually trigger a data refresh:

  1. Find the building in the Data Health panel or the Building Health Ranking table.
  2. Click the building name to open its data health detail.
  3. Click Trigger Refresh.
  4. The refresh runs in the background. Most refreshes complete within a few minutes. Reload the page to see updated figures.
Important: Triggering a refresh for a building with many years of data may take longer. Avoid triggering multiple refreshes for the same building simultaneously. If the refresh fails more than twice, raise a support ticket.
