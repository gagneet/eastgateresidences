Owner Transfer Workflow

A step-by-step guide for owners, strata managers, real estate agents, and the Executive Committee handling unit ownership changes in your building's management portal.

Owner Strata Manager Real Estate Agent EC Member Chairman Super Admin

📋 Overview

When a lot changes hands, the platform must update the strata roll, arrears records, AGM proxies, chat group memberships, and rental certificates — all consistently and automatically. This guide explains how to process an owner transfer and what the system handles for you.

Two pathways:
  1. Quick edit via Owners & Units page — direct field update by Super Admin; all cascades fire immediately.
  2. Owner Transfer Request — formal documented workflow with ownership verification; cascades fire on approval.

✏️ Pathway 1 — Direct Edit (Super Admin)

Use this for quick corrections or when no formal transfer request was submitted.

  1. Navigate to Dashboard → Owners & Units (/dashboard/owners-units).
  2. Find the unit (use the search bar or scroll). Click the Edit icon on the row.
  3. Update Owner Name and any other fields that changed (email, phone, entitlement, occupancy type).
  4. Click Save Changes. The system immediately triggers all cascade side-effects listed below.
Note: Only Super Admins can use direct edit. Strata managers and EC members should use the Owner Transfer Request workflow (Pathway 2).

📝 Pathway 2 — Owner Transfer Request (Formal)

Use this when an owner or staff member needs a documented ownership change request. The workflow creates an audit trail, allows pending requests to be edited before review, and applies approval rules based on the reviewer role.

Step 1 — Owner or authorised staff submits a request

  1. Ensure the incoming owner has already registered on the portal and has an active user account.
  2. Goes to Dashboard → Owner Transfers (/dashboard/admin/owner-transfers) and clicks New Transfer Request.
  3. Selects the unit, enters the incoming owner's email, adds the settlement date if known, and optionally lists any supporting documents.
  4. Submits — request status becomes Pending.
  5. If a mistake is noticed before review starts, the request can still be edited from the same page.

Step 2 — Reviewer approval

  1. Navigate to Dashboard → Owner Transfers. Pending requests appear on the Pending tab.
  2. Click Review on the request to open the review dialog.
  3. Verify the unit, incoming owner details, settlement date, and any supporting documentation.
  4. Choose an action:
    • Approve — Keep Old Owner: Creates new ownership link; old owner record stays active (e.g., co-ownership scenario).
    • Approve — Remove Old Owner: Creates new ownership link and deactivates the old owner's unit relationship (standard sale).
    • Reject: Marks request rejected; no records changed.
  5. Approval routing rules:
    • Super Admin, Strata Manager, or Real Estate Agent: one approval can complete the transfer.
    • EC Member or Chairman: two distinct EC approvals are required before the transfer is processed.
  6. Enter review notes and click Submit Decision.

Step 3 — What happens automatically on approval

All of the following are handled by the system. No further manual steps required.

⚡ Automatic Cascades on Approval

When an owner change is saved (either pathway), the system's _cascade_owner_change function automatically handles the following:

System Area What happens automatically Status
Strata Roll
strata_owners		 Owner name and unit entitlement (UOE) updated in the strata roll. The lot/unit reference numbers are preserved — only the owner name and entitlement are synced. Auto
Arrears Provenance
units.arrears_metadata		 If the outgoing unit has a positive balance_owing, the system snapshots the previous owner's name and the carried arrears amount with a timestamp. This appears in the Arrears Recovery page as "$X.XX carried from [Previous Owner] (YYYY-MM-DD)". Auto
AGM Proxies
agm_attendance		 If the outgoing owner has an active proxy registered for any upcoming AGM, all building admins (strata manager, chairman, super admin) receive an in-app notification to manually void or re-assign the proxy before the meeting. Auto-alert Admin action needed
EC Member Records
ec_members		 If the outgoing owner appears as an EC member (matched by name or email), all building admins receive an in-app notification to review EC membership. The EC record itself is NOT automatically removed — admin must decide whether the outgoing owner remains on the EC. Auto-alert Admin action needed
Chat Groups
chat_groups		 The outgoing owner's user account is removed from all unit-based chat groups (e.g., Apartments chat, Townhouses chat) associated with this building. Auto
Rental Certificates
rental_certificates		 If the unit transitions from tenanted to owner-occupied as part of the transfer, any currently issued rental certificates for that unit are automatically set to superseded. Auto (if occupancy changes)

⚠️ Items That Still Need Admin Action

The following are NOT handled automatically and require a manual step:

  • AGM proxy void / reassignment — You will receive a bell notification if a proxy exists. Go to Dashboard → AGM Management to remove or reassign the proxy vote.
  • EC membership update — You will receive a bell notification if the outgoing owner is listed as an EC member. Go to Dashboard → EC Members to update or remove the record.
  • New owner portal account — The new owner needs a registered account on the portal. If they don't have one, invite them via Dashboard → Users → Invite User or direct them to the self-registration page.
  • Levy correspondence address update — Confirm levy notices will go to the new owner's preferred address. Check their profile under Dashboard → Users.
  • Outstanding arrears recovery — Inherited arrears are flagged automatically in the Arrears Recovery page, but the debt recovery action (issuing a demand letter, payment plan, etc.) remains a manual process.

📄 Required Documentation

For Pathway 2 (formal transfer request), have the following ready before approval:

Incoming owner provides

  • Signed contract of sale (exchange)
  • Title search / transfer document
  • Settlement statement (optional)
  • Current contact details

Strata manager confirms

  • Lot number matches strata plan
  • Settlement date recorded
  • Levy clearance status
  • Any special by-law conditions

❓ Common Questions

Q: What if the new owner already has a portal account?

That's fine. The transfer request references their existing user ID. On approval, their account is linked to the unit with role owner and their role in the system is upgraded if they were previously a tenant or guest.

Q: What if there were arrears before settlement?

The system snapshots the previous owner's outstanding balance and records it in arrears_metadata on the unit. The Arrears Recovery page shows this as inherited arrears. Whether the debt follows the outgoing owner or transfers to the new owner is a legal question — the strata manager should confirm this with the conveyancer. The system does NOT automatically zero out the arrears; it only labels their provenance.

Q: Can I undo an approved transfer?

Not automatically. You would need to manually re-edit the unit record (Pathway 1), deactivate the new owner's unit link in the database, and re-activate the old one. Contact your system administrator if this situation arises.

Q: What if the AGM is next week and the proxy notification fires?

The notification is advisory only — the proxy is NOT voided automatically. You must go to AGM Management → Attendance and remove or re-assign the proxy before the meeting commences.

Q: Does the feature toggle affect this workflow?

The Owner Transfers page is gated by the owner_transfers feature toggle. If the page is inaccessible, a Super Admin can enable it via Dashboard → Feature Toggles.
