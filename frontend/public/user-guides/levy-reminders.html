Levy Reminder Settings

Configure when and how your building sends overdue levy notices to owners

Strata Managers EC Members Chairman

What are levy reminders?

Levy reminders are automated notices sent to owners who have an upcoming or overdue levy payment. Rather than manually emailing individual owners, the system can automatically notify owners at configurable intervals — before the due date as a courtesy, and after as an escalating overdue notice.

Strata managers can fully configure the reminder cadence for your building: which days to send notices, the minimum overdue amount before sending, which channels to use, and how many escalation tiers to send before stopping.

Default reminder cadence

When levy reminders are first enabled for your building, the following defaults apply. All settings are adjustable.

14 days before due date
First courtesy reminder — "Your levy is due in 14 days"
7 days before due date
Second courtesy reminder
3 days before due date
Final courtesy reminder
Due date
1 day overdue — Tier 1
First overdue notice — gentle reminder that payment is past due
7 days overdue — Tier 2
Second overdue notice
14 days overdue — Tier 3
Third overdue notice — more formal tone
30 days overdue — Tier 4
Final notice — maximum escalation tier (default)

After Tier 4 (or whichever tier you set as the maximum), the system stops sending automated reminders. At that point, manual action such as a formal demand letter or legal referral is appropriate.

How to view and update reminder settings

1
Go to Dashboard → Finance → Levy Reminders.
2
The Settings tab shows your current configuration (or defaults if never configured).
3
Adjust any of the following settings:
  • Enabled — toggle reminders on or off for your building
  • Pre-due days — comma-separated list of days before the due date (e.g. 14, 7, 3)
  • Overdue days — days after the due date for each escalation tier (e.g. 1, 7, 14, 30)
  • Minimum overdue amount — owners with less than this amount outstanding will not receive overdue notices (default: $1.00). Useful to avoid notifying owners with trivial rounding differences.
  • Channels — which delivery channels to use (see below)
  • Maximum escalation tier — stop sending after this many overdue tiers (default: 4; maximum: 10)
4
Click Save Settings. Changes take effect on the next scheduled reminder run.

Delivery channels

Channel Status Notes
Email Available Sends a formatted levy reminder email to the owner's registered address. Requires an email provider to be configured in building settings.
In-App Available Sends a bell notification visible in the owner's dashboard notification centre. Available to owners who log in to the portal.
SMS Coming soon SMS delivery is not yet wired. Enabling the SMS toggle has no effect at this time. It is available in settings to configure ahead of the release.
It is recommended to enable both Email and In-App channels. Owners who do not use the portal still receive email notices; portal users see the notification in their bell tray.

Using the dry-run feature

Before dispatching live reminders, you can run a dry run to see exactly which units would receive a notice — without actually sending anything.

1
Go to the Trigger tab on the Levy Reminders page.
2
Ensure the Dry Run toggle is ON (it is on by default).
3
Click Run Preview. The page shows a list of units with outstanding balances that meet the reminder threshold, along with their overdue amounts.
4
Review the list. If you are satisfied with the scope, turn off Dry Run and click Dispatch Live Reminders.
Dry run is always the default. You must explicitly disable it to send live reminders. This prevents accidental bulk sends.

Viewing reminder history

The History tab (or View Log button) shows a paginated list of all reminder runs — both dry runs and live dispatches. Each entry records:

  • When the run was triggered
  • Whether it was a dry run or live
  • How many units were targeted
  • The total outstanding amount across targeted units
  • Who triggered the run

Automatically scheduled runs by the cron job also appear in this log with the action levy_reminder_sent.

How reminders interact with the cron job

The settings you configure are read by the background levy reminders cron job on each scheduled run. The cron job:

  1. Reads your building's reminder settings (or defaults if not configured)
  2. Checks the levy ledger for units with outstanding balances above the threshold
  3. Determines which reminder tier each unit is in based on how many days overdue
  4. Sends notifications via the enabled channels
  5. Logs the outcome to the reminder history

The manual Trigger function fires a Tier 1 reminder run for your building immediately, which is useful for ad-hoc situations or for testing new settings.

Multi-building support

Levy reminder settings are configured per building. Each building can have completely different cadences, channels, and thresholds. Changes to one building's settings have no effect on others.

Frequently asked questions

Will owners receive duplicate reminders if I trigger manually and the cron also runs?
It is possible. Use the manual trigger sparingly and check the history log to see when the last automated run occurred before triggering manually.
Can I turn off reminders entirely for my building?
Yes. Set the Enabled toggle to OFF in settings. The cron job will skip your building while disabled. Live triggers also check this flag (dry runs still work while disabled, so you can still preview).
What counts as "overdue"?
The trigger logic looks at the unit levy ledger for the current year and identifies units whose combined admin and sinking fund balance is at or above the minimum threshold. It does not distinguish between specific quarters — it works on the running balance.
What is the minimum overdue amount for?
Some buildings have small rounding differences or credit adjustments that produce tiny apparent balances. Setting a minimum (e.g. $1.00) prevents reminder emails going to owners who are essentially current.
How do I know if reminders are working?
Check the History log. Every scheduled run appears there. If you expect reminders to have been sent but see nothing in the log, verify that the cron job is running and that the enabled toggle is on.
