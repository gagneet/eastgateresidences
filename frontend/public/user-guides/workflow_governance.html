Overview

Every time-sensitive task that runs automatically in the system — sending levy notices, computing health scores, checking for overdue work orders — is a named workflow. The Workflow Governance page is a single dashboard where you can see the status of every workflow, when it last ran, how healthy it is, and whether it is currently running on schedule.

Navigate to: Dashboard → Admin → Workflow Governance

Workflow Types

⚡ Automated — Cron / Scheduled

Runs automatically on a configured schedule (e.g. daily, weekly, quarterly). Residents cannot trigger these. Strata managers and super admins can run them manually via Run Now.

✋ On-demand — Event / Manual

Triggered by an event (e.g. a maintenance request being overdue) or by a manual request. These do not have a recurring schedule.

Health Status

Status Meaning
Healthy Last run completed successfully within expected time
Stale Last run was successful but older than expected — may indicate a missed schedule
Failing Last run ended with an error. Check the expanded row for details
Never run The workflow has been implemented but never executed yet
Not implemented Planned but not yet built — shown as a placeholder

SLA (Service Level Agreement)

Each workflow has an SLA — the maximum time allowed from trigger to completion. If a workflow exceeds its SLA, it moves to Stale or Failing status.

SLA values are displayed in human-readable format: 4h (4 hours), 2d (2 days), 1w (1 week).

Overriding the SLA

Super Admins and Strata Managers can override the default SLA for any workflow on a per-building basis:

Step 1: Find the workflow row you want to adjust.
Step 2: Click the SLA value in the SLA column. An input box appears.
Step 3: Enter the new SLA in hours (e.g. 2 for 2 hours, 48 for 2 days).
Step 4: Press Enter or click Save. The override is stored per building.

To revert to the default, enter the original SLA hours shown in the workflow catalogue.

Running a Workflow Manually

Strata Managers, Super Admins, and EC Chairmen can manually trigger any implemented workflow:

Step 1: Find the workflow in the table.
Step 2: Click the ▶ Run button in the Actions column.
Step 3: A toast notification confirms the workflow was queued. The run ID is shown.
Step 4: Click Runs to see the run history for that workflow.
Note: Manually triggering a workflow does not reset its schedule. The next automatic run will still occur at the configured time.

Levy-Related Workflows

The following workflows are driven by your building's financial settings:

  • Quarterly Levy Run — schedule set via Site Settings → Financials → Levy due dates
  • Arrears Notice — Tier 1 — triggers based on overdue thresholds in financial settings
  • Levy Arrears Notifier — sends escalation notices per building configuration

To change when these run, go to Dashboard → Admin → Site Settings → Financials.

Filtering by Category

Use the category dropdown to show only workflows in a specific area:

  • Financial — levy runs, arrears notices, budget workflows
  • Compliance — document expiry, regulatory checks
  • Maintenance — work order escalation, PPM scheduling
  • Governance — meeting notices, EC elections
  • Security — login audits, access reviews
  • And more…

Viewing Run History

Click the Runs button on any row to see the last 20 executions of that workflow, including:

  • Start time and duration
  • Status (success, failure, partial)
  • Items processed (e.g. number of levy notices sent)
  • Trigger type (automated vs manual)
  • Error detail (if failed)
