Request Management — Staff Guide

Applies to: Strata Manager EC Chairman EC Member Super Admin

Location: /dashboard/requests (Requests tab) and the smart-request manager queue at /dashboard/smart-request

Who reviews requests?
All incoming requests are visible to every staff role (Strata Manager, EC Chairman, EC Member, Super Admin). Any of these roles can triage, assign, update the status, and close a request. Residents (owners, tenants, guests) can only see their own requests — they cannot see or act on other residents' requests.

1 — The Request Lifecycle

Resident submits via Smart Request (/dashboard/smart-request)
↓
Auto-classification — the system attempts to categorise and optionally auto-resolve levy queries and general enquiries
↓ (if not auto-resolved)
Awaiting Review — request lands in the staff triage queue
↓
Staff assigns to themselves (or a colleague) and sets status to In Progress
↓
If more information is needed: set to Awaiting Resident — SLA timer pauses
↓
Once actioned: add resolution notes and set to Closed

2 — Accessing the Request Queue

From the Smart Request page (recommended for triage)

  1. Go to /dashboard/smart-request
  2. Staff roles automatically see a Management Queue panel above the resident submission form
  3. Use the filter tabs — Open, In Progress, Resolved, All — to switch views
  4. Overdue requests are highlighted with a red border and an Overdue badge

From the Requests page

  1. Go to /dashboard/requests
  2. The My Requests tab shows all requests for the building when you are a staff role
  3. Use the structured tabs (Maintenance, Insurance, Pet, etc.) to filter by request type

Triage stats panel

At the top of the management queue you will see live metrics:

Metric What it means
Auto-resolved today Requests answered instantly by the system (no staff action needed)
Deflection rate (7 days) Percentage of all requests that were auto-resolved — higher is better
Received this week Total new requests in the last 7 days

3 — Status Reference

Status Meaning Who sets it
Auto-Resolved System answered the request instantly (e.g. levy balance query). No staff action required. System
Awaiting Review Request received, not yet assigned. SLA clock is running. System (on creation)
In Progress A staff member has taken ownership and is actively working on it. Staff
Awaiting Resident Staff needs more information from the resident. SLA is paused. Staff
Closed Request fully resolved and archived. Resident notified. Staff
Overdue SLA deadline has passed without resolution. Shown as a warning — not a final status. System (computed)

4 — How to Triage a Request

Step 1 — Open the request
Click a request row in the management queue to view its full details and activity timeline.
Step 2 — Review the auto-classification
The system displays the detected category (e.g. maintenance_request) and a confidence score. If confidence is below 70%, a Needs Human Review flag is shown — the classification may be wrong, so read the description carefully before proceeding.
Step 3 — Assign to yourself
Use the Assigned To dropdown to assign the request. This records your name on the request and notifies the resident that their request is being handled.
Step 4 — Change the status
Use the status dropdown (inline in the queue row, or on the detail page) to move the request to In Progress. You can also type a note — this is appended to the activity timeline visible to the resident.
Step 5 — Resolve and close
Once the matter is resolved, add Resolution Notes summarising what was done, then set the status to Closed. The resident receives a notification with your notes.

6 — The Triage Queue (Attention Required)

Go to the triage dashboard via the morning card on your dashboard, or navigate directly to /dashboard/smart-request. The triage queue is split into three buckets:

Bucket What it contains Sort order
Overdue Requests where SLA has already been breached Oldest first — most urgent at the top
Needs Review Requests flagged for human review (low auto-classification confidence) Newest first
Due Soon Requests with SLA expiring within the next 2 hours Soonest deadline first

7 — Adding Resolution Notes

Resolution notes are visible to the resident in their activity timeline. Write them clearly, as you would in an email — avoid internal shorthand. Good examples:

  • "Plumber attended on 22 April. Tap washer replaced in common bathroom, ground floor. No further action required."
  • "Levy balance as at 21 April 2026: $0 outstanding. All instalments are current."
  • "Pet application approved by the EC at the April meeting. A pet bond of $500 applies. Refer to By-Law 18."

8 — Request Reference Numbers

Every request is assigned a unique reference number in the format REQ-YYYY-NNNN (e.g. REQ-2026-0042). Use this number when communicating with residents or when escalating to a contractor or legal advisor.

Tip — Checking the Morning Card
Your dashboard's Morning Card will alert you when there are requests with a breached SLA. The card includes a count (e.g. "3 requests past SLA") and a direct link to the requests page. Check your dashboard at the start of each working day.

10 — Notifications Sent to Residents

The system automatically notifies residents at the following events:

  • Request submitted — acknowledgement with reference number and expected SLA
  • Auto-resolved — immediate answer sent (e.g. levy balance)
  • Status changed to In Progress — confirmation that staff has taken ownership
  • Status changed to Awaiting Resident — prompt to supply the requested information
  • Status changed to Closed — resolution notes delivered to resident
