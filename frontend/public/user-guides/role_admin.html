Super Admin Resident Handbook

The Super Admin role is responsible for the technical configuration, security, and administrative management of the your building platform.

High Privilege Role

You have access to all system data and configurations. Use these permissions carefully to maintain system integrity and user privacy.

System Configuration

  • Site Settings: Manage global platform parameters, including contact information and branding.
  • Feature Toggles: Enable or disable specific modules (e.g., Chat, Marketplace, Bookings) building-wide.
  • External API Access: Enable or disable the External API for integrations and control API availability for third parties.
  • Email Configuration: Set up and test system-wide email templates and delivery settings.
  • Scraper Settings: Configure data synchronization with external property and utility providers.
  • Building Management: Create, edit, and switch between building profiles in the multi-tenant platform.
  • Rate Limiting: Control global API throttling from Site Settings (toggle + multiplier).

Administrative Management

  • User Directory & Access Control: Manage all user accounts, approve registrations, and assign granular permissions.
  • Units & Owners: Maintain the master database of units, lot numbers, and current owners.

  • Audit Logs: Monitor comprehensive system logs for security and troubleshooting purposes.

Multi-Building Context

Super Admins can switch active building context using the header building selector. This updates the tenant-scoped view across dashboards, requests, and reporting. Always confirm the selected building before making changes.

Registration Notifications

When a new user submits the registration form, you receive an immediate bell notification (🔔) in the top navigation bar.

  • Bell icon: Shows a count badge for unread notifications. Click to expand the list.
  • Direct link: Each registration notification links directly to /dashboard/users with the registrant's name pre-filled in the search box — no manual searching required.
  • Email alert: An email is sent to all Super Admins and the Chairman with the same pre-populated link.

Reviewing a Registration

  1. Click the bell notification or the link in the email.
  2. The Users page opens with the registrant's name already in the search field.
  3. Find the pending user and expand their record.
  4. Choose one of three actions:
    • Approve — grants full dashboard access immediately.
    • Request Profile Info — sends the user a bell notification and email asking them to update their profile details. Their status changes to Info Requested.
    • Reject — archives the account and notifies the user.

Owner Name Mismatch Alert

For owner registrations only, the Users page shows a warning triangle (⚠️) if the registered full name does not closely match the name on the strata roll (from the units collection). This helps catch typos or incorrect names before approval.

  • The comparison is fuzzy — it ignores punctuation, case, and common title words (Mr, Mrs, Ms, Dr).
  • Tenants, guests, and service providers are excluded from this check.

Returning Archived Users

If a previously archived user re-registers with the same email address, the system does not create a duplicate account. Instead it captures their new details for your review and keeps the original archived record untouched (required for the 7-year compliance retention period).

  1. The user fills in the registration form as normal. They see a blue informational banner confirming their return request has been submitted.
  2. You receive a bell notification and email showing the old vs. new details side-by-side (name, unit, end date). The email links directly to Expired & Archived Accounts.
  3. Go to Admin → Expired & Archived Accounts and find the record with the Return Requested indicator.
  4. Click Restore. The system will:
    • Apply the new name, phone, and end date from the return request to the live account.
    • If the user requested a different unit, deactivate the old unit assignment and create a new one for the new unit.
    • Re-activate the user's building membership (always happens, regardless of unit change).

Note: Only super admins can restore archived users. If the new unit is already occupied by another active resident of the same role, the restore will fail with a conflict error — the account is not modified. Resolve the existing occupancy first (e.g. archive or reassign the current occupant), then retry the restore.

Advanced Financial Enhancements

As Super Admin, you have full access to all advanced financial tools on the platform.

Arrears Recovery Board

Access and manage the Debt Recovery Board at Dashboard → Debt Recovery Board. Units in arrears are classified across four severity tiers:

  • Monitor — Balance owing, no action yet taken.
  • Contacted — Section 83 notice has been sent (within 14 days).
  • DCA Eligible — More than $1,500 owing and 14+ days have elapsed since the notice.
  • DCA Referred — Formally referred to a Debt Collection Agency.
Screenshot placeholder: Arrears Recovery Board – 4-tier severity view

Generate Section 83 Notice

Issue a formal demand letter under Section 83 of the Unit Titles Management Act 2011 (ACT) directly from the Debt Recovery Board. The PDF is auto-generated and can be sent to the owner or retained for compliance records.

DCA Referral

Refer a unit to a Debt Collection Agency when arrears exceed $1,500 and at least 14 days have passed since the Section 83 notice was issued. All referrals are logged in the recovery audit trail.

Special Levies

Create one-off special levy charges allocated across all units by their Unit of Entitlement (UOE) at Finance → Special Levies.

Bank Reconciliation

Record and verify monthly bank statement entries at Finance → Bank Reconciliation. Match payments against the platform's financial records and mark statements as reconciled.

Payment Plans

Create structured instalment arrangements for owners in arrears at Finance → Payment Plans. Set the schedule, instalment amounts, and monitor compliance over time.

Record Expenses & Income

  • Record Expenses: Log building expenses against approved budget categories to maintain accurate fund tracking.
  • Record Income: Log non-levy income such as bank interest, rebates, and grants.

Financial Health Score

The Financial Health Score (0–100) provides a composite view of the building's financial position based on seven components: Surplus Ratio, Arrears Percentage, Cashflow Buffer, Forecast Stability, Budget Discipline, Expense Volatility, and Reserve Adequacy.

Financial Onboarding — Historical Reconstruction

Navigate to Dashboard → Financial → Financial Onboarding (or Historical Reconstruction directly) to add or reconstruct a building's financial history after it has already been onboarded — for example a building migrating onto the platform with incomplete or no prior payment records. As Super Admin you have full access to every stage of the workflow, including the two actions restricted to Super Admin only: reversing a batch, and applying a levy-item GST regeneration.

Creating a batch offers a Generation source choice: Generate from proposed budget (the default, building-agnostic — computes owner levy payments directly from the building's proposed Admin/Sinking/GST budget, automatically skipping any lot/year/fund period that already has a real recorded payment) or Link existing Demo Bank rows (an older option that only works if matching Demo Bank rows already exist for the building). A status card on the page tells you upfront whether the building has any existing financial history for the selected years before you commit to generating anything.

Full operator workflow, including the two-person review/approve control and what Reverse does and does not undo: Historical Reconstruction guide.

Access Control Management

Navigate to Dashboard → Admin → Access Control Management (/dashboard/admin/user-permissions) to manage the 14 granular permission flags for individual users, independent of their role defaults.

Understanding the Permission System

Every user inherits a set of default permissions based on their role (e.g., Owners can view finances; Tenants cannot). The Access Control page lets you elevate or restrict individual users beyond those defaults without changing their role.

Three states per permission:
  • Default (grey) — follows the role's default for this permission.
  • Elevated (green badge) — explicitly granted beyond the role default.
  • Restricted (red badge) — explicitly denied even if the role would normally grant it.

How to Modify Permissions

  1. Select a user from the left panel (use the search box or role filter to narrow the list).
  2. The right panel shows the user's current permissions grouped into six categories: Documents, Financial, Communication, Governance, Administration, Operations.
  3. Toggle individual permissions on or off. Each row shows the role default label so you can see whether your change is an elevation or restriction.
  4. An amber save bar appears at the top whenever you have unsaved changes. Click Save Changes to apply.
  5. To revert all changes for a user back to their role defaults, click Role Defaults (reset button in the user summary card).

Feature Access Controls

Navigate to Dashboard → Admin → Feature Access Controls (/dashboard/admin/user-feature-permissions) to grant or restrict access to specific feature pages for individual users, independently of their role and the site-wide feature toggle.

The Three-Layer Access Model

Feature access is evaluated in three layers, in order:

  1. Site-Wide Toggle — the feature toggle in Feature Toggles (/dashboard/admin/feature-toggles) controls the default availability of the feature for the entire building. When it is OFF, the feature is hidden for everyone except users with an explicit per-user Grant override and the chairman/super_admin roles.
  2. User Override — a Super Admin can grant or deny access to a specific user, overriding the site toggle by explicitly Granting access even when the site toggle is OFF or Denying access even when it is ON (within the constraints above for chairman/super_admin).
  3. Effective Access — the computed result shown as a green check or red X in the Override column. This is what the user actually experiences.
Super Admin bypass: This role always has effective access to all features regardless of site toggles or per-user overrides. Overrides cannot restrict Super Admin access.

Override States

Override State Meaning Button Style
Site Default No override set — access follows the site-wide toggle. Grey (neutral)
Grant User is explicitly granted access even if the site toggle is OFF. Green
Deny User is explicitly denied access even if the site toggle is ON. Red

How to Set an Override

  1. Select a user from the left panel. Their override count badge shows how many features have active overrides.
  2. The right panel shows all 63 features grouped into categories (Core, Financial, Governance, etc.).
  3. Use the search box, category filter, or Overrides only toggle to find specific features quickly.
  4. Each feature row shows: the site toggle state, an inline 3-button override selector, and the computed effective access badge.
  5. Click Site Default / Grant / Deny to change the override. The change saves immediately (no save button needed).
  6. To clear all overrides for the selected user at once, click Clear All Overrides.

Rate Limiting & Security Throttling

All authentication endpoints enforce per-IP rate limits to protect against brute-force and credential-stuffing attacks. Limits are configurable from Site Settings → Registration & Approvals → Rate Limiting, and can be scaled globally using the multiplier.

Endpoint Default Limit Purpose
POST /auth/register 5 / minute Prevent bulk account creation
POST /auth/login 10 / minute Prevent password brute-force
POST /auth/forgot-password 5 / minute Prevent email enumeration via timing
POST /auth/reset-password 5 / minute Prevent token brute-force
POST /auth/change-password 10 / minute Prevent credential stuffing
POST /auth/registration-decision 10 / minute Protect one-click owner approval links

When a limit is exceeded: the endpoint returns HTTP 429 Too Many Requests. The portal displays a user-friendly message ("Too many attempts — please wait a moment"). Limits reset after 60 seconds per IP.

To change limits: navigate to Site Settings → Registration & Approvals, scroll to the Rate Limiting card, update the values and multiplier, and save. Changes apply within about a minute for new requests. To disable rate limiting entirely, use Feature Toggles → Rate Limiting (Super Admin only).
