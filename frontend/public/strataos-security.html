Manual Checks

Immediate Action Item Spot-Checks

Four targeted manual checks from the security test spec run against the production endpoint.

  • ✅

    FastAPI docs not exposed in production

    GET /docs → 404  |  GET /openapi.json → 404  ·  APP_ENV=production disables all three doc endpoints in the FastAPI constructor.

  • ✅

    Unauthenticated response — no internal leakage

    GET /api/buildings/me (no token) → {"error":{"code":"UNAUTHENTICATED","status":401}} — clean JSON, no stack traces, no MongoDB driver details, no framework version.

  • ✅

    JWT secret strength ≥ 32 chars

    Secret is ≈ 42 characters — above the RFC 7518 §3.2 minimum for HS256. Verified by character count on backend/.env, never logged or committed.

  • ✅

    building_id query params are authorisation-gated

    BI endpoints accept building_id as a query param but call _require_manager(user, building_id) before use — super-admin context switching is by design, not a privilege escalation vector.

Why It Passed

Core Security Architecture

The platform passed all tests due to foundational architectural decisions that enforce security at multiple layers simultaneously.

🛡️ Tenant Isolation — TenantScopedDatabase

The TenantScopedDatabase wrapper automatically injects building_id into every query. Users are mathematically prevented from reading data outside their strata plan — even if the application layer has a bug.

🗄️ PostgreSQL Row-Level Security

RLS policies on core.lots, core.schemes, and core.feature_toggle_overrides enforce tenant isolation at the database engine level. Bypass UUID patterns are deliberately absent from core.lots.

🚫 NoSQL Injection Blocking

Strict Pydantic v2 validation rejects MongoDB operator objects ($ne, $gt) at the API gateway. No injected operator ever reaches the Motor driver.

🔐 Cryptographic Integrity

JWTs signed with HS256 + 42-char entropy secret. Algorithm validation is strict — alg:none, RS256, and HS512 substitution attacks all rejected. Tokens now include iat and jti for replay detection.

⚡ Dynamic Rate Limiting

Rate limits load from db.site_settings every 60 seconds with per-endpoint multiplier support. IP resolution uses CF-Connecting-IP → X-Real-IP chain — header spoofing from untrusted peers is blocked.

🧱 Pydantic Model Boundary

All write endpoints use explicit Pydantic models (UserUpdate, etc.) that silently strip undeclared fields. Privilege-escalation fields like is_super_admin, building_ids, and raw permissions never reach the DB layer.

🔑 TOTP Challenge Path

The codebase includes a TOTP setup, verify, status, disable, and challenge router under /auth/totp. This is an implemented identity control, but it is not counted as a separate finding in this audit summary.
