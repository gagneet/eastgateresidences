Role note: chairman is not a top-level system role — it is ec_position=CHAIRMAN on a user whose role is ec_member. Role lists on this page naming "chairman" alongside real role names are shorthand for this; see permissions.md for the full contract.

Feature key: invoice_ocr  |  Branch: feat/parse-invoices-payment-integration  |  Updated: 2026-04-22

Overview

The Invoice OCR pipeline allows strata managers to upload PDF and image invoices/quotes from contractors. Claude Vision (Anthropic) is used as the primary OCR engine to extract vendor details, ABN, line items, GST, and totals. Mindee Invoice v4 is used as a fallback when Claude Vision is unavailable or returns low confidence. If both fail, an empty scaffold is returned for manual entry.

On confirmation, the system:

  1. Validates the reviewed data (non-zero total, vendor name present)
  2. Writes a financial_transaction expense record to the financial ledger
  3. Generates a payment receipt PDF (stored as base64 on the document record)
  4. Marks the invoice_documents record as confirmed

Configuration (backend/.env)

Variable Required Notes
ANTHROPIC_API_KEY Required for Claude OCR If absent, Claude step is skipped; falls back to Mindee or empty scaffold.
MINDEE_API_KEY Optional fallback Mindee free tier covers 250 pages/month (~$0 for 5–10 invoices). If absent, Mindee step is skipped.

Cost estimate: ~$0.17/month for 10 invoices via Claude Vision (claude-sonnet-4-6, ~3k input tokens + 500 output tokens per invoice at $3/$15 per MTok).

OCR pipeline — services/invoice_ocr_service.py

parse_invoice(file_bytes, file_type)
  ├── ANTHROPIC_API_KEY set?
  │     └── extract_with_claude()  → confidence >= 0.5? → return result
  │                                  confidence  < 0.5? → fall through
  ├── MINDEE_API_KEY set?
  │     └── extract_with_mindee()  → return result
  └── _empty_result()              → ocr_source="manual", all amounts 0.0

Claude Vision content block

PDFs are sent as a document content block; JPEG/PNG/WebP as an image block. No image-conversion library is required — Anthropic accepts PDF bytes directly.

{
  "type": "document",        // or "image" for JPEG/PNG/WebP
  "source": {
    "type": "base64",
    "media_type": "application/pdf",
    "data": "<base64-encoded bytes>"
  }
}

Extracted JSON schema (Claude prompt output)

{
  "vendor_name": "ABC Plumbing Pty Ltd",
  "abn": "12 345 678 901",
  "invoice_number": "INV-001",
  "invoice_date": "YYYY-MM-DD",
  "due_date": "YYYY-MM-DD",
  "line_items": [
    { "description": "Emergency repair", "qty": 1.0, "unit_price": 450.00, "total": 450.00 }
  ],
  "subtotal": 450.00,
  "gst": 45.00,
  "total": 495.00,
  "suggested_fund": "admin",
  "confidence": 0.92,
  "ocr_source": "claude_vision"
}

Markdown fences (```json ... ```) are stripped before JSON parsing. If Claude returns non-JSON, the error is caught and execution falls through to Mindee.

API endpoints

All endpoints require authentication (require_feature("invoice_ocr")) and can_manage_finances permission. Roles: super_admin, chairman, strata_manager, ec_member.

POST /api/invoices/upload-and-parse

Upload a PDF/image file. Runs OCR and creates a pending_review record. Returns parsed preview.

Content-Type: multipart/form-data

Form field Type Notes
file File PDF, JPEG, PNG, or WebP. Max 20 MB.
document_type string "invoice" or "quote". Default: "invoice".

Response: InvoiceDocumentResponse (see Models section). file_data is stripped from response.

Errors: 400 unsupported file type, 400 file > 20 MB, 403 non-finance role.

GET /api/invoices

List all invoice documents for the current building.

Query param Type Notes
status string? Filter: pending_review, confirmed, rejected.
document_type string? Filter: invoice or quote.

Response: InvoiceListResponse. file_data and receipt_data are excluded from projection (bandwidth optimisation).

GET /api/invoices/{invoice_id}

Get a single invoice record including full parsed_data and confirmed_data. file_data is stripped; receipt_data is included (needed for receipt download indicator). 404 if not found or belongs to a different building.

POST /api/invoices/{invoice_id}/confirm

Confirm (possibly edited) OCR data, create a financial_transaction, generate receipt PDF.

Body: InvoiceConfirmRequest (see Models). Validations: total > 0, vendor_name non-empty.

Errors: 404 not found, 409 already confirmed, 400 zero total, 400 blank vendor.

Side effects: inserts to financial_transactions (Mongo path) or posts to Postgres journals via adapter (PG path); updates invoice_documents status to confirmed. Finance-page expense actuals read from transaction aggregation, so confirmed OCR invoices are reflected in Budget-vs-Actual/Quarterly Budget once the transaction is present in financial_transactions (immediate on Mongo path, relay-backed on PG path).

DELETE /api/invoices/{invoice_id}

Hard-delete a pending_review invoice. Confirmed invoices cannot be deleted (7-year retention).

Response: 204 No Content.

Errors: 404 not found, 409 confirmed invoice.

GET /api/invoices/{invoice_id}/receipt

Download the receipt PDF for a confirmed invoice. Returns application/pdf with Content-Disposition: attachment.

Errors: 404 not found, 404 receipt not yet generated.

Important: This endpoint requires a JWT Bearer token. Do not use bare <a href> links — the browser strips the Authorization header. Use a programmatic axios blob download instead.

InvoiceConfirmRequest (POST body)

  "vendor_name": "ABC Plumbing Pty Ltd",   // required, non-empty
  "abn": "12 345 678 901",                  // optional
  "invoice_number": "INV-001",              // optional

}

InvoiceDocumentResponse (GET/POST response)

{
  "id": "uuid",
  "building_id": "13195",
  "status": "pending_review | confirmed | rejected",
  "document_type": "invoice | quote",
  "file_name": "plumbing_invoice.pdf",
  "file_type": "application/pdf",
  "file_size_bytes": 142000,
  "ocr_source": "claude_vision | mindee | manual",
  "ocr_confidence": 0.92,
  "parsed_data": { /* OCR output dict */ },
  "confirmed_data": { /* InvoiceConfirmRequest fields */ },
  "transaction_id": "uuid or null",
  "receipt_generated": false,
  "receipt_data": "base64 PDF or null",     // present only on single-record GET and confirm response
  "created_at": "ISO-8601",
  "created_by": "user_id",
  "confirmed_at": "ISO-8601 or null",
  "confirmed_by": "user_id or null"
}

Note: file_data (base64 original file) is never returned in any response. receipt_data is excluded from list responses to reduce bandwidth.

MongoDB collection — invoice_documents

Building-scoped. All queries use building_id as the primary partition key via the TenantScopedDatabase wrapper, which auto-injects building_id into every query.

Index Fields Notes
Status query (building_id, status) List by status filter
Time sort (building_id, created_at DESC) Default list order
Unique lookup (id, building_id) unique Single-record GET

Indexes are created by financial_repository.ensure_indexes(), called at server startup.

Status lifecycle

upload-and-parse → pending_review
                   ↓ (confirm)
               confirmed         ← permanent, cannot be deleted
                   ↓ (future)
               rejected          ← reserved, not yet implemented

Storage note

file_data stores the original file as base64. For the current scale (5–10 invoices/month) this is acceptable. At higher volume, consider migrating to object storage (S3-compatible) and storing only a URL reference.

Financial transaction created on confirm

On confirmation, financial_repository.insert_transaction() is called with:

{
  "building_id": "<current building>",
  "financial_year": "<derived from invoice_date year>",
  "fund_type": "admin | sinking",
  "category_name": "<category from confirm body>",
  "transaction_type": "expense",
  "amount": <total>,
  "gst_amount": <gst>,
  "description": "Invoice INV-001 — ABC Plumbing Pty Ltd",
  "reference": "<invoice_number>",
  "transaction_date": "<invoice_date>",
  "supplier_name": "<vendor_name>",
  "created_by": "<user_id>",
  "source": "invoice_ocr"
}

The source: "invoice_ocr" field allows future reports to distinguish OCR-originated transactions from manually entered ones.

Security considerations

Concern Mitigation
File upload safety scan_upload() is called before OCR. File type is validated against an allowlist (application/pdf, image/jpeg, image/png, image/webp). Max 20 MB enforced server-side.
Building isolation All queries include building_id. The TenantScopedDatabase wrapper auto-injects the building context. Cross-building access returns 404.
Role guard _finance_roles() checks effective_role or role — never raw user["role"] — to handle elevated users correctly.
Receipt download auth The receipt endpoint requires a JWT Bearer token. Frontend uses programmatic axios blob download (not a bare <a href>) to ensure the header is sent.
Retention Confirmed invoices cannot be hard-deleted (409). 7-year ACT/NSW strata retention compliance.
Test data All records created by tests must carry is_test_data: true to prevent appearing in production dashboards.

Error reference

Status Endpoint Cause
400 upload-and-parse Unsupported file type (not PDF/JPEG/PNG/WebP)
400 upload-and-parse File exceeds 20 MB
400 confirm Total amount is zero or negative
400 confirm Vendor name is blank or whitespace-only
401 any Missing or expired JWT token
403 any Role does not have can_manage_finances (tenant, owner, guest)
403 any Feature toggle invoice_ocr disabled for this building
404 get / confirm / delete / receipt Invoice not found or belongs to a different building
404 receipt Receipt not yet generated (invoice not confirmed)
409 confirm Invoice is already confirmed
409 delete Invoice is confirmed — deletion blocked by retention policy
