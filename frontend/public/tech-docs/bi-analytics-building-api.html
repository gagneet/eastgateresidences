BI Analytics — Building-Level Endpoints

All endpoints use prefix /api/bi. Served from backend/routers/bi.py. Toggle: bi_analytics_building_enabled.

Authentication & Role Guard

All building endpoints require an authenticated, approved user with one of:

  • super_admin, strata_admin, strata_manager, ec_member

Role check uses effective_role (never raw user["role"]) to handle elevated owners correctly. The inline guard pattern (_require_manager) is used per CLAUDE.md.

Financial Endpoints

Metric contract (GAP-FIN-040): levy_collection_rate / collection_rate are the Due-date Collection Rate (canonical get_collection_rate_metrics() → due_date_collection_rate()): receipts allocated to charges due as-of-today ÷ charges due as-of-today. This is not full-year levy coverage / fund health and must never be labelled interchangeably. total_outstanding / arrears figures are per-unit (unit_arrears_and_credit()); a credit on one unit never nets against another unit's arrears.

GET /bi/building/{building_id}/financial-summary

Financial KPI summary: levy collection %, arrears total, fund balances.

Query ParamTypeDescription
financial_yearstringe.g. "2026". Defaults to current year.

Response fields: wrapped in {data, building_id, source}. Current service keys include levy_collection_rate, total_levied, total_paid, total_outstanding, total_arrears, admin_fund_balance, sinking_fund_balance, and source. Amounts are API dollar values, not *_cents fields.

GET /bi/building/{building_id}/levy-collection-trend

Monthly levy collection rate trend for charting. Returns up to 12 months of data.

Response: array entries currently use {month, charged, paid, collection_rate, source}.

GET /bi/building/{building_id}/arrears-hotspots

Top arrears lots ranked by outstanding balance. Maximum 20 results.

Response: array entries currently include lot_number, total_outstanding, days_overdue, arrears_band, optional owner_name, and source.

GET /bi/building/{building_id}/sinking-fund-projection

10-year sinking fund projection from capital plan. Uses analytics.fact_financial_balance when PG primary is enabled; falls back to sinking_fund_plan MongoDB collection.

Response: service returns a projection object with projection, shortfall_risk, shortfall_years, and source.

GET /bi/building/{building_id}/capex-vs-plan

Capital expenditure actuals versus planned amounts for current year.

Response: array entries are year-level {year, planned, actual, variance, variance_pct, source} records.

GET /bi/building/{building_id}/health-trend

Historical building financial health score trend (monthly, 6-month window).

Response: array entries include date, overall_score, component scores, health_label, and source.

GET /bi/building/{building_id}/sinking-fund-risk

Risk assessment of sinking fund adequacy against upcoming capital works.

Response: same shape as sinking-fund-projection; this route is a scoped owner/manager risk view.

Maintenance Endpoints

GET /bi/building/{building_id}/maintenance-costs

Monthly maintenance spend breakdown by category.

Query ParamTypeDescription
monthsintLookback window (default 12, max 24)

Response: {total_cents, by_category: [{category, spend_cents, request_count}], trend}.

GET /bi/building/{building_id}/request-heatmap

Maintenance request volume by day-of-week and hour for operational scheduling.

Response: 7×24 matrix of request counts.

Compliance Endpoints

GET /bi/building/{building_id}/compliance-status

Current compliance certificate status across all regulatory domains.

Response: array of {domain, status, expiry_date, days_remaining, rag_status} covering: fire_safety, electrical, pool_safety, lift, WHS, insurance, AGM.

Occupancy & Utility Endpoints

GET /bi/building/{building_id}/occupancy-mix

Lot occupancy type distribution (owner-occupied vs. tenanted vs. vacant).

Response: {owner_occupied_pct, tenanted_pct, vacant_pct, total_lots}.

GET /bi/building/{building_id}/utility-trend

Common property utility consumption trend (water, electricity) by month.

Response: array of {month, water_kl, electricity_kwh, cost_cents}.

Asset Risk

GET /bi/building/{building_id}/asset-risk

Asset health scores and replacement risk ranking for the building's registered assets.

Response: array of {asset_name, health_score, age_years, replacement_due_year, risk_level}.

ETL & Cutover

GET /bi/admin/etl-status

ETL freshness report per building: last run timestamp, row counts per fact table, staleness flag. Role: super_admin only.

GET /bi/building/{building_id}/cutover-status

Pre-cutover readiness checklist for enabling bi_pg_primary_enabled on a specific building. Returns per-check pass/fail and a summary ready_for_cutover boolean.

POST /bi/admin/etl/run

Trigger an ETL refresh for one or all buildings. Role: super_admin only.

POST /api/bi/admin/etl/run
{ "building_id": "13195" }   // or omit for all buildings

GET /bi/access

Returns the caller's BI access map: which tiers and buildings they can access, and which toggles are active. Useful for frontend conditional rendering.

Alerts

GET /bi/building/{building_id}/alerts

Active BI-derived alerts for the building (arrears threshold breach, sinking fund shortfall risk, compliance deadline within 30 days, asset replacement overdue). Returns ordered by severity.

Response: array of {alert_type, severity, message, action_url}.
