Finance API Reference

This reference documents the finance endpoints affected by the current GST and tenant-scoping model.

Cross-cutting rules

  • All requests are building-scoped.
  • Administrative and Sinking Fund source values are treated as ex-GST.
  • Owner-facing levy totals are derived using Site Settings fields gst_registered and levy_gst_rate.
  • APIs should normalize legacy per-UOE storage where raw values are historically ambiguous.

Key endpoints

Endpoint Purpose Notes
GET /api/annual-levies Return annual levy summaries Per-UOE values should be exposed as normalized owner-payable rates.
GET /api/annual-levies/{year} Return one annual levy summary Use building-scoped settings before presenting levy rates.
GET /api/levy-calculator Calculate levy allocations per unit Derive payable amounts from ex-GST fund totals plus GST settings.
GET /api/finance/quarterly-budget Quarterly finance summary Expose GST metadata and building-aware totals.
PUT /api/settings Update building Site Settings Includes levy timing, branding, and GST behavior.

GST-related response fields

{
  "gst_registered": true,
  "gst_rate": 0.10,
  "gst_label": "GST (10%)",
  "admin_per_uoe_annual": 30.9882,
  "admin_per_uoe_payable_annual": 34.08702,
  "total_per_uoe_payable_annual": 44.03751
}

Use the payable fields for owner-facing totals. Use the ex-GST fields for administrative planning displays.

Implementation note

The recommended derivation order is:

  1. use explicit ex-GST fund totals
  2. apply building GST settings
  3. use trust billing targets only where exact current-year billing needs penny-safe allocation
  4. treat stored raw per-UOE legacy values as compatibility fallbacks, not primary truth

Portal-to-Finance Bridge Endpoints (updated 2026-04-17)

The Civium portal scraper writes to four snapshot collections. Finance endpoints JOIN these at query time. Data is never copied into levy system collections (single source of truth rule).

GET /api/finance/portal-bank-balances

Returns live bank account balances from the portal scraper snapshot. Requires can_view_finances.

GET /api/finance/portal-actuals?year=YYYY

Returns budget-vs-actual from the portal scraper, mapped to Australian financial year. Levy year "2026" maps to financial_year "2025-2026". Requires can_view_finances. 

{
  "year": "2026",
  "financial_year": "2025-2026",
  "categories": [
    {
      "category": "Insurance",
      "fund": "admin",
      "planned": 42000.00,
      "actual": 41500.00,
      "variance": 500.00
    }
  ],
  "totals": {
    "admin": { "planned": 340870.20, "actual": 318000.00, "variance": 22870.20 },
    "capital_works": { "planned": 99504.90, "actual": 88000.00, "variance": 11504.90 }
  }
}

Fund mapping: portal "admin" = levy system "administrative"; portal "capital_works" = levy system "sinking".

Portal Sync Read Endpoints (added 2026-04-17)

The portal scraper bridge populates levy_categories, annual_levies, and unit_levy_ledger after every sync. Finance pages read from these collections. Two additional read-only endpoints expose the raw portal snapshot:

Endpoint Purpose Source collection
GET /api/strata/financials Raw budget vs actual categories from portal scrape strata_financials
GET /api/strata/owners Per-unit outstanding balance from portal strata_owners
GET /api/strata/sync/status Last sync job metadata and building summary building_summaries

Data provenance flags

Important: is_synthetic=True records in annual_levies and data_source="scraper" records in unit_levy_ledger were created by the bridge. They will be refreshed on the next sync.

Records with is_synthetic=False (CSV upload / AGM-ratified) are authoritative — the bridge never overwrites their income fields (proposed_admin_expenses, proposed_sinking_expenses).

For the full sync architecture including write model, bridge logic, and migration steps, see strata-sync.html.
