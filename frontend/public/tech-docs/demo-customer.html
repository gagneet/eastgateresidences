Demo Customer Seed

Technical reference for backend/seeds/demo_customer.py — Phase F-Zero (May 2026)

Overview

The demo customer seed creates a fully-populated demonstration tenant — Acme Strata — with scheme number UP-DEMO-001. It is idempotent (safe to re-run), wired into scripts/deployment/deploy.sh, and produces a self-consistent 6-layer dataset for showcasing all platform features.

Seed layers

# Layer Key records
1 Organisation Acme Strata Management Pty Ltd — SM org with branding, contact details
2 Scheme / Building UP-DEMO-001 — 14 lots, ACT jurisdiction, scheme class A
3 Tenant Postgres core.tenants row linked to scheme; is_demo=true
4 Lots 14 core.lots rows; lot numbers 1–14 with entitlement schedule
5 Users / personas manager@acme-demo.com · owner@acme-demo.com · tenant@acme-demo.com; all in MongoDB + Postgres
6 Levies Current-year admin + sinking levy schedule in MongoDB annual_levies

Running the seed

cd backend
# Via deploy.sh (recommended — auto-runs on every deploy)
bash scripts/deployment/deploy.sh --seed

# Manual run (idempotent)
source venv/bin/activate
python3 seeds/demo_customer.py

Idempotency rules

  • All upserts use ON CONFLICT DO NOTHING (Postgres) and update_one(upsert=True) (MongoDB).
  • Users are matched by email — re-running does not reset passwords.
  • Levy records are keyed by (building_id, year, fund_type) — re-running patches the existing row.
  • is_demo=true is set on the scheme; all seed data includes is_test_data=false (demo data is real demo content, not transient test data).

Multi-tenant isolation

All MongoDB documents use building_id: "UP-DEMO-001". All Postgres rows use the tenant_id UUID resolved from core.tenants WHERE scheme_number = 'UP-DEMO-001'. East Gate data (building_id: "13195") is never touched.

Feature toggles

Demo building inherits global feature toggle defaults. Building-level overrides can be applied via the admin console. The Acme demo rollout now enables the canonical Postgres cutover toggle set for current-balance finance and trust reads, with banking.provider and banking.mode both set to mock. The broader external API levy-summary toggle remains OFF until levy runs/items are migrated into Postgres for the demo scheme.

Removing demo data

Demo data is flagged with is_demo=true on the scheme. To remove the demo customer, use the soft-archive API (DELETE /portfolio/buildings/UP-DEMO-001) — never hard-delete.
