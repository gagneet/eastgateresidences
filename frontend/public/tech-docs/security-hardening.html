P0-01: Mail Password Encryption

Before (Gap): mail_password stored in plain text in MongoDB users collection.
After (Fixed): mail_password encrypted with Fernet symmetric encryption on write; decrypted on read. Migration script for existing records provided.

How It Works

  • backend/utils/crypto.py — thin wrapper around utils/encryption.py
  • encrypt_sensitive(plain_text) — uses existing ENCRYPTION_KEY from config.py
  • decrypt_sensitive(cipher_text) — backward-compatible (returns plain text if not encrypted)
  • is_encrypted(value) — detects enc: prefix to avoid double-encryption

Migration

python3 scripts/db/migrate_encrypt_mail_passwords.py

Idempotent — safe to run multiple times. Skips already-encrypted values.

Affected Endpoints

  • GET /api/mail/access — decrypts on read
  • PUT /api/mail/update-password — encrypts on write
  • PUT /api/mail/admin-update-password — encrypts on write
  • POST /api/admin/reset-user-passwords — encrypts on write (reset_mail branch)

P0-03: Bulk Document Move BOLA Fix

Before (Bug): POST /api/documents/bulk-move referenced an undefined building_id variable, causing a NameError at runtime. Query was also not scoped by uploader for non-admins.
After (Fixed): building_id variable removed from query (was never in function scope); non-admin users are now correctly limited to their own documents via uploaded_by filter.

GAP-001: send_email_async Signature Fix

Before (Critical Bug): _notify_parcel_residents() called send_email_async(body=...). The function signature is html_content=. This caused the function to receive the email content as an unexpected kwarg, silently fall through to "no email provider configured", and return {success: False} — no email ever sent.
After (Fixed): All calls use html_content=. Also added context="parcel_notification" so parcel notifications are visible in the email audit log.

GAP-001: create_user_notification db= Parameter Fix

Before (Critical Bug): Previous version passed db= to create_user_notification(). The function imports db internally — passing it as a kwarg causes TypeError: unexpected keyword argument 'db', silently killing every in-app notification.
After (Fixed): The new implementation uses create_notifications_batch(notifications, building_id=building_id) — batch operation, correct signature.

GAP-001: TenantScopedDatabase Awareness

Before (Potential Bug): user_units.find({"building_id": building_id, ...}) — manually injecting building_id into queries on a TenantScopedDatabase that already adds building_id, causing "duplicate building_id in $and" MongoDB error (documented in database.py).
After (Fixed): Query uses only unit_number + is_active + role_at_unit — trusts the wrapper to scope by building.

ENCRYPTION_KEY Usage

The codebase already has ENCRYPTION_KEY in config.py, used by the Asset Register. This key is now also used for mail password encryption via utils/crypto.py. No new environment variables or key derivation schemes are needed.
