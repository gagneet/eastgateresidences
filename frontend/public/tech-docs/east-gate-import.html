East Gate Historical Import

Technical reference for the C4 CSV import endpoints — Phase F-Zero (May 2026)

Overview

Three onboarding-wizard endpoints allow bulk import of historical data from CSV files. They consume the exact CSV formats produced by the C1 East Gate import package (imports/east_gate_2026_05_03/) and are suitable for any building onboarded with pre-existing financial history.

All three endpoints are idempotent — re-uploading a file for the same building replaces existing records rather than duplicating them.

Endpoint summary

Endpoint CSV files Target storage
POST /onboarding/scheme/{session_id}/import-historical-financials CSVs 06–10 MongoDB: historical_annual_levies, historical_levy_issuances, historical_financial_snapshots
POST /onboarding/scheme/{session_id}/import-owner-transfers CSV 05 Postgres: core.parties, core.ownership_periods
POST /onboarding/scheme/{session_id}/import-opening-balances CSV 11 step_data['opening_balances'] in core.onboarding_sessions

CSV formats

CSV 05 — Owner transfers

lot_number, unit_number, effective_from, effective_to,
new_owner_name, previous_owner_name, transfer_date,
sold_price_aud, source, confidence, notes
  • effective_from / effective_to: ISO dates (YYYY-MM-DD). Leave effective_to blank for current owner.
  • Rows are validated for non-overlapping periods per lot (EXCLUDE USING gist constraint in Postgres).
  • A bitemporal predecessor record is auto-inserted for the earliest transfer: valid_from=1900-01-01, valid_to=effective_from - 1 day.

CSVs 06–10 — Historical financials

Formats vary per file; all share building_id context injected automatically from the session.

  • CSV 06: levy issuances — one row per lot per levy year
  • CSVs 07–09: annual levy summaries per fund type and year
  • CSV 10: arrears snapshots (as-at date, outstanding amounts)

CSV 11 — Opening balances at cutover

fund_type, opening_balance_amount, as_at_date,
bsb, account_number, account_name, evidence_source, notes
  • fund_type values: "Administrative Fund" → "admin", "Sinking Fund" → "sinking", "Special Levy Fund" → "special".
  • Amounts are stored as cents (integer). Input can be decimal dollars.

Import-based vs clean-state finalize

POST /onboarding/scheme/{session_id}/finalize detects whether any import was uploaded:

  • If step_data contains opening_balances OR historical_financials_summary → session is treated as import-based.
  • Genesis journal posting is skipped for import-based sessions (deferred to Phase F-prime).
  • The finalize response includes "import_based": true and captured summaries.

Authorization

All three endpoints require an active onboarding session owned by the caller, resolved via _resolve_session(session_id, current_user). The session must not yet be finalized. Building context (set_ctx_building_id) is set automatically from the session's scheme_number.

Idempotency

All import endpoints call delete_many({building_id: ...}) on the target collection before inserting. Re-uploading a CSV for the same building fully replaces the previous import. This makes wizard retry flows safe.
