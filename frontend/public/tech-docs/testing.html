Testing Reference

How tests are organised across the platform, the commands to run each suite, and the patterns every new test must follow — multi-tenant isolation, idempotent setup, AsyncMock for the Mongo wrapper, and a teardown() for every k6 script.

Quick Commands

Always use the backend venv Python. System Python lacks the project's pinned dependencies and will fail at import time. Never run pytest from the global interpreter. 
# Backend — full suite
backend/venv/bin/python3 -m pytest tests/backend -q

# Single file
backend/venv/bin/python3 -m pytest tests/backend/test_schema_sync.py -q

# Single test
backend/venv/bin/python3 -m pytest tests/backend/test_navigation.py::TestNavigationConfig::test_navigation_config_mode_is_valid -q

# Frontend — full Jest suite
cd frontend && yarn test --watchAll=false

# Single Jest file
cd frontend && yarn test --testPathPatterns=BIAnalyticsPage --watchAll=false

# Playwright (E2E)
npx playwright test tests/frontend/
npx playwright test tests/frontend/e2e/rental-certificates.spec.js --reporter=list

# Performance (k6)
k6 run tests/performance/maintenance_benchmark.ts -e BASE_URL=http://localhost:8003/api -e AUTH_TOKEN=<token>
k6 run --env BASE_URL=... --env AUTH_TOKEN=... -e K6_SCENARIO=smoke tests/performance/<feature>_benchmark.ts

# Makefile shortcuts (from project root)
make test-backend
make test-frontend
make test            # both

Backend Tests (pytest)

Mocking the Mongo wrapper

Motor methods are coroutines. Use AsyncMock for every DB call — MagicMock fails silently inside asyncio.gather(). 

from unittest.mock import AsyncMock, MagicMock, patch

mock_db = MagicMock()
mock_db.maintenance_requests.find_one = AsyncMock(
    return_value={"id": "x", "building_id": "13195", "title": "..."},
)
mock_db.maintenance_requests.insert_one = AsyncMock(
    return_value=MagicMock(inserted_id="x"),
)

# Cursor for find() — return an object with .to_list()
cursor = MagicMock()
cursor.to_list = AsyncMock(return_value=[{"building_id": "13195", "...": "..."}])
cursor.sort = MagicMock(return_value=cursor)
mock_db.collection.find.return_value = cursor

Setting building context

Tenant-scoped collections require a building context before any DB call. Without it the wrapper raises RuntimeError at query time. 

from utils.request_context import set_ctx_building_id

@pytest.mark.asyncio
async def test_levy_summary_for_east_gate():
    set_ctx_building_id("13195")
    result = await get_levy_summary(year="2026")
    assert result["building_id"] == "13195"

Mocking permissions

from utils.permissions import Permission

with patch("utils.permissions.get_user_permissions") as mock_perms:
    mock_perms.return_value = Permission(can_manage_requests=True, ...)
    result = await my_endpoint(...)

Patching the right module

Auth helpers moved to routers/auth.py in Session 56. Patch with patch("routers.auth.send_email_async"), NOT patch("server.send_email_async"). Functions still living in server.py (shared utilities) include create_token, get_current_user, hash_password, and verify_password.

Rate-limited endpoints

Functions decorated with @limiter.limit(...) require a real Request object when called directly. Construct a minimal Starlette scope and pass it as request=: 

from starlette.requests import Request as StarletteRequest

scope = {
    "type": "http", "method": "POST", "path": "/api/auth/login",
    "query_string": b"", "headers": [], "client": ("127.0.0.1", 12345),
}
req = StarletteRequest(scope)
result = await login(request=req, email="x@y.com", password="...")

Frontend Tests (Jest + RTL)

Radix UI gotchas

  • TabsTrigger needs fireEvent.mouseDown, not fireEvent.click.
  • Dialog content needs waitFor after the trigger.
  • Components rendering a Tooltip must be wrapped in a <TooltipProvider> in tests.

Role guards in client components

Pages that gate on isAdmin() / isManager() must check loading first — otherwise the guard fires before the session resolves and redirects every user to /dashboard. Tests should mock useAuth and verify the loading=true branch before assertions. 

jest.mock("@/contexts/AuthContext", () => ({
  useAuth: () => ({
    user: { role: "ec_member", unit_number: "TH017" },
    loading: false,
    isManager: () => true,
    isAdmin: () => false,
  }),
}));

API mocks

The api axios instance returned by useAuth() has baseURL = ${NEXT_PUBLIC_BACKEND_URL}/api. Never prefix calls with /api/ in production code or in tests — that produces a double-prefix and a 404.

End-to-End Tests (Playwright)

Playwright covers user-visible flows. Specs live under tests/frontend/ and run against a local dev server (or a deployed environment via BASE_URL). 

# Run everything
npx playwright test tests/frontend/

# Single spec
npx playwright test tests/frontend/e2e/rental-certificates.spec.js --reporter=list

# UI mode (interactive)
npx playwright test --ui

# Codegen against production
npx playwright codegen https://eastgateresidences.com.au

Reports land in tests/reports/html/. Open the latest with npx playwright show-report tests/reports/html.

Security E2E Suite

Security specs in tests/frontend/e2e/security/ exercise BOLA, mass assignment, and cron endpoint protection. Two layers: bola-strataos.spec.ts (Layer 1) and bola-strataos-layer2.spec.ts (Layer 2 — ID format validation, horizontal BOLA, cron discovery).

Rate limit bypass required for security tests: Both spec files run beforeAll token acquisitions in parallel. Without disabling rate limiting, the login endpoint returns 429 for the second worker and the suite fails with an unhelpful error. Set DISABLE_RATE_LIMIT=1 in the backend environment when running these specs: 
# backend/.env (dev/CI only — never production)
DISABLE_RATE_LIMIT=1

# Then run security specs
npx playwright test tests/frontend/e2e/security/ --project=security
Login retry pattern: Layer 2 beforeAll hooks use a 3-attempt exponential back-off loop (2s, 4s) in case transient rate-limiting still occurs: 
let t: string | null = null;
for (let attempt = 0; attempt < 3; attempt++) {
  t = await getToken(email, password);
  if (t) break;
  if (attempt < 2) await new Promise(r => setTimeout(r, 2000 * (attempt + 1)));
}
if (!t) throw new Error('Login failed after 3 attempts');

Performance Tests (k6)

Every k6 script MUST include a teardown() function that deletes any test data it created. Use a deterministic title prefix (e.g. "Perf test request perf-") so teardown can filter precisely. Reference: tests/performance/maintenance_benchmark.ts. 
// Skeleton: tests/performance/<feature>_benchmark.ts
import http from "k6/http";
import { check, sleep } from "k6";

export const options = {
  scenarios: {
    smoke: { executor: "constant-vus", vus: 1, duration: "30s" },
    load:  { executor: "ramping-vus", startVUs: 0,
             stages: [{ duration: "30s", target: 20 },
                      { duration: "1m",  target: 20 },
                      { duration: "30s", target: 0  }] },
  },
  thresholds: {
    http_req_failed: ["rate<0.01"],
    http_req_duration: ["p(95)<500"],
  },
};

export function setup() {
  // Create any pre-conditions here, return them to the default function.
}

export default function () {
  const res = http.post(`${__ENV.BASE_URL}/maintenance`, JSON.stringify({
    title: `Perf test request perf-${__VU}-${__ITER}`,
    building_id: "13195",
    is_test_data: true,
  }), { headers: { Authorization: `Bearer ${__ENV.AUTH_TOKEN}`, "Content-Type": "application/json" } });
  check(res, { "status is 201": (r) => r.status === 201 });
  sleep(1);
}

export function teardown() {
  // MUST clean up — title prefix filter
  http.del(`${__ENV.BASE_URL}/maintenance?title_prefix=Perf+test+request+perf-`,
           null, { headers: { Authorization: `Bearer ${__ENV.AUTH_TOKEN}` } });
}

Running the whole suite (one command)

scripts/testing/run_k6_suite.py runs every tests/performance/*_benchmark.{ts,js} against a running backend, captures per-script logs + k6 summary exports, classifies each as pass / threshold-fail / runtime-fail / timeout, and writes a dated report bundle under docs/performance/k6_run_<date>/ (status.tsv, logs/, summaries/, and a JSON + HTML coverage report). It exits non-zero if any script did not pass, so CI can gate on it.

Prerequisites: a running backend (uvicorn server:app … --port 8003), k6 on PATH, a JWT in AUTH_TOKEN, and a BUILDING_ID (scheme number, e.g. 13195 or UP-DEMO-001). Get a token from the login endpoint (use a super-admin account so one token drives every building via the X-Building-ID override the benchmarks send): 
AUTH_TOKEN=$(curl -s -X POST http://localhost:8003/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"<user>","password":"<password>"}' \
  | python3 -c 'import sys,json;d=json.load(sys.stdin);print(d.get("access_token") or d.get("token",""))')
scripts/get_token.py is a dev shortcut but is hardcoded to one user/building — edit it first. The runner prints WARNING: AUTH_TOKEN is not set … if you skip this: it still runs, but authenticated scripts fail their checks. Full run guide: docs/performance/running_performance_tests.md. 
# Preview the script list + static coverage WITHOUT running k6 (no backend needed):
python scripts/testing/run_k6_suite.py --list

# Full run against a local backend (env is forwarded to every script via -e):
BASE_URL=http://localhost:8003/api AUTH_TOKEN=<jwt> BUILDING_ID=<scheme_number> \
  python scripts/testing/run_k6_suite.py

# Subset + smoke scenario + explicit output dir:
python scripts/testing/run_k6_suite.py --only bi_benchmark,intelligence_benchmark \
  --scenario smoke --out docs/performance/k6_run_2026-08-11

Forwarded env when set: BASE_URL, AUTH_TOKEN, BUILDING_ID, UNIT_NUMBER, LOT_NUMBER, FINANCIAL_YEAR, API_KEY, UI_BASE_URL, SESSION_COOKIE, INCLUDE_PLATFORM, INCLUDE_PDF, INCLUDE_WRITES, CLEANUP_TOKEN, ORG_ID, AGENCY_ID, MANAGER_ID, OWNER_ID, LEGAL_PAGE. Flags: --only, --skip, --scenario, --per-script-timeout, --out, --list. "Backend route patterns touched" in the report is best-effort static coverage (a route path is referenced by a k6 script), not branch/role/state coverage.

External API v1 (k6 + Postman)

The partner-facing /api/v1 surface authenticates with an X-API-Key header (not a JWT). Run it in either tool: 

# k6 — all /v1 GET reads (+ opt-in writes via INCLUDE_WRITES=1)
k6 run tests/performance/external_api_benchmark.ts \
  -e BASE_URL=http://localhost:8003/api -e API_KEY=<partner_key>

# newman — each request asserts status + a per-endpoint response-time budget
newman run tests/performance/postman/strataos_external_api_v1.postman_collection.json \
  -e tests/performance/postman/strataos_external_api_v1.postman_environment.json \
  --iteration-count 20
The External API is append-only (no partner DELETE for defects/quotes/invoices), so writes are opt-in, must target a demo/staging building, and use the perf-ext- prefix so backend/scripts/cleanup_perf_test_maintenance.py (or a supplied CLEANUP_TOKEN) can remove them.

Cron / worker timing harness (not k6)

Background jobs are not HTTP routes, so k6 cannot reach them. tests/performance/harness/cron_worker_timing.py times the scheduler JOBS registry and cron run_* entrypoints — one run each, wall-clock + throughput vs a per-job budget. It is safe-by-default: read-only jobs always run, dry-run-capable jobs only under --dry-run, and mutating jobs are skipped unless --allow-mutation + PERF_HARNESS_ALLOW_MUTATION=1 (all-building mutating jobs also need --allow-all-buildings). Point it at staging, never production. 

# List the catalogue (no backend deps needed):
python tests/performance/harness/cron_worker_timing.py --list

# Safe default (read-only jobs) + dry-run recompute, JSON summary:
python tests/performance/harness/cron_worker_timing.py \
  --building-id 13195 --dry-run --json-out /tmp/cron_timing.json

UI page performance (Lighthouse, not k6)

k6 measures API latency, not what the browser does (render, hydration, layout shift, bundle cost). tests/performance/ui/lighthouse_runner.mjs runs Lighthouse against a list of pages (routes.json) and checks the real user-facing metrics — performance score, LCP, TBT, CLS, FCP, TTI, Speed Index, byte weight — against per-page budgets (budgets.json), writing a report to docs/performance/ui_lighthouse_<date>/. Deps are isolated from the frontend lockfile. 

# Preview routes + budgets (no deps/Chrome needed):
node tests/performance/ui/lighthouse_runner.mjs --list

# Install once, then run public pages (frontend on :3000):
cd tests/performance/ui && npm install && cd -
UI_BASE_URL=http://localhost:3000 node tests/performance/ui/lighthouse_runner.mjs

# Include authenticated pages — supply a NextAuth session cookie from the browser:
UI_BASE_URL=http://localhost:3000 COOKIE='next-auth.session-token=…' \
  node tests/performance/ui/lighthouse_runner.mjs

Auth pages are skipped (not failed) when COOKIE is unset. Run against a production build (yarn build && yarn start, port 3020) for representative numbers. Tune budgets.json to your first clean baseline before gating in CI. Details: tests/performance/ui/README.md.

Swagger / OpenAPI drift guard

The published External API contract (frontend/public/tech-docs/strataos-openapi.json, generated by scripts/docs/generate_api_artifacts.py) must match the live router. scripts/validation/validate_external_api_openapi.py (and its pytest tests/backend/test_external_api_openapi_sync.py) AST-parses backend/routers/external_api.py and fails if any /api/v1 operation is missing from — or stale in — the spec. Pure stdlib, so it runs in CI without a backend. A non-zero exit means "regenerate the API artifacts and commit them."

Multi-Tenant Rules

The most important rule on this page. Every test must prove that data scoped to one building_id never leaks into a query for another building_id.
  1. Every mock document MUST include building_id.
  2. Assert cross-building isolation: data seeded for "13195" must not appear in results for "16244".
  3. Call set_ctx_building_id(bid) before any function that touches the DB wrapper.
  4. Use admin_staff as the role name in fixtures (reception is a UI alias only).
  5. Feature-toggle-gated features MUST have tests for both toggle-on and toggle-off paths.
  6. Use "is_test_data": True on every record created by a test or k6 script. Production queries filter via {"is_test_data": {"$ne": True}}.

Isolation pattern

@pytest.mark.asyncio
async def test_levy_summary_isolation(mock_db):
    # Seed both buildings
    mock_db.unit_levy_ledger.find.return_value.to_list = AsyncMock(
        return_value=[
            {"building_id": "13195", "unit": "TH017", "total_levied": 4806.27},
            {"building_id": "16244", "unit": "U101",  "total_levied": 3200.00},
        ],
    )
    set_ctx_building_id("13195")
    result = await get_levy_summary(year="2026")
    units = [r["unit"] for r in result["units"]]
    assert "TH017" in units
    assert "U101" not in units, "16244 data leaked into 13195 result"

Common Patterns

Idempotent fixtures

Tests must clean up after themselves and tolerate being re-run on a non-empty DB. Use unique title prefixes per run (perf-${run_id}-${i}), and prefer delete_many({"is_test_data": True, "title": {"$regex": "^perf-..."}}) in teardown over a blunt delete_many({}).

Toggle coverage

@pytest.mark.parametrize("toggle_enabled", [True, False])
async def test_invoice_ocr_respects_toggle(toggle_enabled, mock_db):
    mock_db.feature_toggles.find_one = AsyncMock(
        return_value={"key": "invoice_ocr", "is_enabled": toggle_enabled,
                      "building_id": "13195"},
    )
    set_ctx_building_id("13195")
    if toggle_enabled:
        result = await upload_invoice(...)
        assert result["ocr_status"] == "queued"
    else:
        with pytest.raises(HTTPException) as exc:
            await upload_invoice(...)
        assert exc.value.status_code == 403

Effective role

Backend role guards must read _effective_role(user), not user["role"]. Tests for elevated users (temp_elevation active) must set effective_role on the mock user. 

mock_user = {
    "id": "u_owner_with_ec_elevation",
    "role": "owner",
    "effective_role": "ec_member",
    "building_id": "13195",
    "unit_number": "TH017",
}

CI & Pre-Deploy Checklist

The mandatory post-implementation checklist (see CLAUDE.md Step 2) requires every change to add or update tests in three places:

  • Backend pytest under tests/backend/
  • Frontend Jest/RTL under tests/frontend/unit/ OR a Playwright spec under tests/frontend/
  • k6 performance script under tests/performance/ with a teardown() function

Before opening a deploy: 

# From repo root
make test                                                      # backend + frontend
backend/venv/bin/python3 -m pytest tests/backend -q            # if only backend changed
cd frontend && yarn test --watchAll=false && yarn build   # if only frontend changed
npx playwright test tests/frontend/                            # E2E sanity check

The deploy script (bash ./scripts/deployment/deploy.sh) runs the test suite by default. Pass --skip-tests only if you have a documented reason — never as a shortcut.
