Dashboard v2 Extras API

Auxiliary owner-dashboard signals endpoint. Introduced in PR #428 (May 2026).

Endpoint

GET /api/analytics/dashboard-v2-extras

Authentication

Requires a valid Bearer JWT (get_approved_user dependency). The building context is resolved automatically from the JWT or the X-Building-ID header (super-admin override).

Query Parameters

ParameterTypeRequiredDescription
unit_numberstringNoRequest per-unit signals (market estimate, cost categories, badges, open requests). Omit for building-wide signals only.

Authorization

When unit_number is supplied and differs from the requesting user's own unit, the caller must hold one of: super_admin, strata_manager, strata_admin, or ec_member. Owners may only request their own unit's signals. Returns HTTP 403 otherwise.

Response Schema

{
  "building_id": string,
  "unit_number": string | null,

  // Building-scope signals
  "emergency_contacts": [
    { "label": string, "phone": string, "detail": string | null }
  ],
  "market_signals": {
    "suburb_label": string,
    "median_levy_pct_delta": number | null,    // YoY % change in median levy
    "unit_estimate": number | null,            // AUD market estimate for this unit
    "suburb_median": number | null,
    "unit_yoy_pct": number | null,
    "rental_yield": number | null,
    "days_on_market": number | null,
    "building_premium_pct": number | null,
    "trend_7yr": number[],                    // 7 monthly data points
    "comparable_sales": [
      {
        "address": string,
        "sold_price": number,
        "sold_date": string,       // YYYY-MM-DD
        "bedrooms": number,
        "type": string             // "apartment" | "townhouse" etc.
      }
    ]
  },
  "cost_categories": [
    { "name": string, "annual": number, "color": string | null }
  ],
  "cost_yoy_delta_pct": number | null,

  // Insurance — live data from insurance_policies collection when available;
  // seeded fallback for demo buildings; {} if no policy exists.
  "insurance": {
    "renews_on": string | null,        // ISO date e.g. "2026-11-15"
    "no_premium_hike": boolean | null,
    "source": "live" | "seeded"       // present only when live data is used
  },

  // Unit-scope signals (only when unit_number supplied)
  "badges": {
    "active_voter": boolean,
    "event_host": boolean
  },
  "owner_requests": [
    {
      "id": string,
      "reference": string,
      "status": string,          // "in_progress" | "awaiting_owner" | "overdue"
      "title": string,
      "summary": string | null,
      "needs_reply": boolean
    }
  ],

  "source": "seeded" | "empty"   // "empty" when building has no signals documents
}

Data Sources

Field groupPrimary sourceFallback
Emergency contacts, market signals, cost categories, badgesdb.dashboard_v2_signals (building/unit scope)Empty array/object — frontend renders CTA state
Insurance renewal datedb.insurance_policies — most recent active/pending_renewal policy for the buildingdb.dashboard_v2_signals seeded value; then {}
Owner open requestsdb.dashboard_v2_signals unit-scope seed (demo buildings)Frontend also fetches GET /workflow-requests?limit=5 and prefers live data when non-empty
Note: owner_requests in this endpoint contains seeded demo data only. The owner dashboard also calls GET /workflow-requests?limit=5 in parallel and uses live results when available, falling back to these seeded entries for demo buildings.

Frontend Usage

Fetched in frontend/src/app/(dashboard)/dashboard/page.tsx as part of the main Promise.all. Result passed as data.dashboard_v2_extras to OwnerDashboard, which distributes it to:

  • BuildingStrengthCard — insurance signal
  • ThisWeekActions — week action rows
  • TrueCostBreakdown — cost categories + YoY delta
  • MarketIntelExpanded — market signals
  • YourRequestsCard — owner requests (fallback) + emergency contacts

Seed Data

Demo building UP-DEMO-001 (StrataOS Residences) is seeded by backend/seeds/demo_customer.py layer layer_7_dashboard_v2_signals. Run python3 seeds/demo_customer.py to seed; idempotent.
