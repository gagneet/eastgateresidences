Scheduler Architecture — Technical Reference

Phase 6 introduces two complementary async task systems: ARQ for routine periodic financial jobs, and Temporal.io for durable, multi-step workflows that require human-in-the-loop signals or long-running coordination. Both are gated by the financial_integration_layer_v2 feature toggle per building.

Feature Toggle Guard

Every ARQ task and the legacy scheduler's nightly_merkle_seal check the financial_integration_layer_v2 toggle before executing:

  • Toggle OFF → legacy APScheduler / cron path runs unchanged.
  • Toggle ON → ARQ task owns the job; scheduler skips it.

Toggle resolution order: per-building record → global default (building_id=None).

GenerateLeviesWorkflow

Workflow ID convention: levygen:{building_id}:{quarter}

Step Activity Timeout Purpose
1 compute_lot_levies 5 min Calculate per-lot levy amounts from budget
2 allocate_crns 5 min Assign Customer Reference Numbers (synthetic fallback if CRN service unavailable)
3 create_levy_documents 10 min Persist levy records (idempotent upsert)
4 send_levy_notices 15 min Email owners (respects TEST_EMAIL_INTERCEPT_ADDRESS in dev)

ReconciliationCloseWorkflow

Workflow ID convention: recon-close:{building_id}:{period_id}

Step Activity / Signal Purpose
1 run_reconciliation_check Compare journal entries sum vs bank statement total
2a (balanced) → step 3 Proceed directly to close
2b (discrepancy) notify_reviewer_activity + wait for reviewer_approved signal Email strata manager; human must approve before close proceeds
3 close_period_activity Transition period to CLOSED state (validates state machine)

Production Deployment Paths

Option A — Temporal Cloud (Recommended)

No infrastructure to maintain. Change only these env vars:

TEMPORAL_HOST=your-namespace.tmprl.cloud:7233
TEMPORAL_NAMESPACE=your-namespace.accountId
TEMPORAL_TLS_CERT=/path/to/client.pem
TEMPORAL_TLS_KEY=/path/to/client.key

Option B — Self-Hosted (Docker Compose)

# docker-compose.temporal.yml provides postgres + temporal server
docker compose -f docker-compose.temporal.yml up -d
TEMPORAL_HOST=localhost:7233 venv/bin/python3 -m workers.temporal_worker

Rebuild Projection CLI

Safe idempotent script to rebuild a financial projection from source data:

cd backend

# Full rebuild of unit_levy_ledger for building 13195
venv/bin/python3 scripts/rebuild_projection.py unit_levy_ledger --building 13195

# Incremental rebuild since a given event ObjectId
venv/bin/python3 scripts/rebuild_projection.py lot_balances_projection \
    --building 16244 \
    --since 6634e1a0000000000000000a

Supported projection names: unit_levy_ledger, lot_balances_projection, levy_payments_projection (last two are aliases for unit_levy_ledger).

Multi-Tenant Isolation

  • All ARQ tasks accept building_id as first arg; _job_id includes it to prevent cross-building deduplication collisions.
  • Temporal workflow IDs embed building_id as prefix — Temporal deduplicates by workflow ID, so concurrent runs for different buildings are independent.
  • The rebuild CLI and projection_rebuild_task inject building_id in every aggregation $match stage.
