Maintenance PDF Generation

Role note: chairman is not a top-level system role — it is ec_position=CHAIRMAN on a user whose role is ec_member. Role lists on this page naming "chairman" alongside real role names are shorthand for this; see permissions.md for the full contract.

The maintenance module generates Purchase Order (PO) and Invoice PDFs on demand. PDFs are returned as streaming responses and include the requesting building's registered strata address in the document footer — no hardcoded addresses.

Endpoints

Method Path Returns Auth
GET /maintenance/{request_id}/purchase-order/pdf application/pdf streaming strata_manager, super_admin, chairman
GET /maintenance/{request_id}/invoice/pdf application/pdf streaming strata_manager, super_admin, chairman

Handler Flow — Purchase Order PDF

sequenceDiagram participant C as Client participant H as get_purchase_order_pdf() participant DB as db.maintenance_requests participant S as get_general_settings_or_default() participant G as generate_purchase_order_pdf() C->>H: GET /maintenance/{id}/purchase-order/pdf H->>DB: find_one({_id, building_id}) DB-->>H: maintenance doc (or None → 404) H->>S: get_general_settings_or_default(building_id) S-->>H: {strata_address, plan_number, ...} H->>G: generate_purchase_order_pdf(po_data, building_settings=settings) G-->>H: pdf_bytes (ReportLab) H-->>C: StreamingResponse(pdf_bytes, media_type="application/pdf")

The Invoice PDF flow is identical — only the generator function differs (generate_invoice_pdf).

Building Address Resolution

Both generators resolve the footer address from building_settings using this priority chain:

address = (
    building_settings.get("strata_address")
    or building_settings.get("building_address")
    or ""
)

The strata_address field is the canonical value stored in db.settings (tenant-scoped by building_id). building_address is accepted as a fallback for legacy documents.

Multi-tenant guarantee: get_general_settings_or_default(building_id) always queries db.settings scoped to the requesting building's building_id. A Sierra (16244) request will never show East Gate's (13195) address in the footer.

Generator Signatures

# backend/utils/pdf_generator.py

def generate_purchase_order_pdf(
    po_data: dict,
    building_settings: dict = None,
) -> bytes: ...

def generate_invoice_pdf(
    invoice_data: dict,
    building_settings: dict = None,
) -> bytes: ...

When building_settings=None, the address footer is omitted (empty string). This cannot happen in production because the handler always passes the settings result — but None is accepted to keep the generators testable in isolation.

Error Handling

Condition HTTP Status Detail
Maintenance request not found 404 "Maintenance request not found"
Request belongs to different building 404 (DB query includes building_id filter)
Caller role not in allowed set 403 "Permission denied"
PDF generation exception 500 "Failed to generate PDF"

PDF Content

Purchase Order

  • PO Number, Issue Date
  • Vendor name and address
  • Line items table: description, quantity, unit price, total
  • GST summary and grand total
  • Authorised by (strata manager name)
  • Footer: building strata address + plan number

Invoice

  • Invoice Number, Invoice Date, Due Date
  • Vendor details
  • Line items table with GST
  • Payment reference instructions
  • Footer: building strata address + plan number

Testing

Two test files cover PDF generation at different layers:

File Layer Tests
tests/backend/test_pdf_generator_po_invoice.py Pure unit — generator functions directly 35 — address in footer, multi-tenant isolation, GST, empty fields
tests/backend/test_maintenance_pdf_handlers.py Handler — DB mock + generator mock 17 — 403/404/500 paths, building_settings passed correctly, StreamingResponse
PDF text assertions use pdfminer.high_level.extract_text(io.BytesIO(pdf_bytes)). Raw byte-string search (b"text" in pdf_bytes) does not work because ReportLab compresses content streams with ASCII85+FlateDecode.
