Server-Sent Events (SSE)

Real-time push notifications replacing polling — B2-01

Architecture

SSE replaces the 5-second polling loop previously used in ChatPage.jsx and NotificationsPage. The backend maintains an in-memory per-user queue; events are pushed over a long-lived HTTP connection using the SSE protocol.

Components

  • backend/routers/sse.py — SSE endpoint + push_to_user helper
  • sse-starlette>=1.8.0 — SSE response wrapper
  • In-memory _connections: dict[str, asyncio.Queue] registry

Endpoint

GET /api/events/stream

Authentication

JWT can be provided via:

  • Authorization: Bearer <token> header (preferred — programmatic clients)
  • ?token=<jwt> query parameter (fallback for browser EventSource)

Response Format

event: parcel_logged
data: {"unit_number": "TH017", "carrier": "Australia Post"}

event: chat_message
data: {"group_id": "grp-1", "message": {...}}

event: notification
data: {"title": "📦 Parcel Arrived", "message": "...", "type": "parcel", "link": "/community/parcels"}

event: heartbeat
data: {}

Event Types

Event Triggered By Payload
parcel_logged POST /parcels unit_number, carrier
chat_message POST /chat/groups/{id}/messages group_id, message
notification create_user_notification() title, message, type, link
heartbeat 30s timeout (automatic) (empty)

Backend Usage

from routers.sse import push_to_user
import asyncio

# Push a parcel_logged event to the resident
asyncio.create_task(
    push_to_user(user_id, "parcel_logged", {"unit_number": "TH017", "carrier": "AusPost"})
)

push_to_user is a no-op if the user is not connected — safe to call unconditionally.

Frontend Usage

// Native browser EventSource (fallback token via query param)
const token = getAccessToken();
const es = new EventSource(`/api/events/stream?token=${token}`);

es.addEventListener("parcel_logged", (e) => {
  const data = JSON.parse(e.data);
  console.log("Parcel for unit:", data.unit_number);
  // Refresh parcel list...
});

es.addEventListener("heartbeat", () => {
  // Keep-alive — no action needed
});

es.onerror = () => {
  // Browser automatically reconnects after 1s delay
};

Deployment Considerations

  • Process-local: The connection registry is in-memory. Multi-process deployments (Gunicorn with multiple workers) require a Redis pub/sub adapter. Current single-process Uvicorn deployment is fine.
  • Cloudflare / nginx: Ensure proxy_read_timeout and buffering are disabled for SSE paths. The 30s heartbeat keeps the connection alive through typical 60s idle timeouts.
  • CORS: SSE is same-origin by default. The existing allow_origins=* configuration in server.py covers CORS for SSE.
  • Queue backpressure: Each connection queue is capped at 100 events. Overflow events are silently dropped — the client will resync on the next page load or via API polling fallback.
