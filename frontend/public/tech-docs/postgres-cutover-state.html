PostgreSQL Cutover State

Where the Mongo → Postgres migration actually is, measured live 2026-08-29 — and what still has to happen.

The headline

Nobody chose MongoDB. The routers were written against Mongo before Postgres existed, and the cutover was built as a control plane — tables and toggles that decide which store should serve a read — without ever rewiring the 1,292 route handlers to ask it.

10 of 133 router files consult the control plane. 103 call db.<collection> directly, with no dispatch at all. So the control plane can say “Postgres is promoted for finance” — and it does — and nothing changes, because routers/work_orders.py has never heard of it.

Control plane — all eight domains promoted

core.domain_cutover_status for East Gate (13195) holds finance_ledger, governance, identity_core, occupancy, powerhouse_conversations, settings, trust_ledger and trust_reconciliation, all at mode=postgres_write, readiness=promoted. Every other building is Mongo-served.

This corrects a claim that stood in CLAUDE.md until 2026-08-29, which said four domains were promoted and that finance/trust/powerhouse had no row at all. That was true when written; the rows were restored on or about 2026-08-28. core.cutover_audit_log holds 25,568 domain_source.missing_state_defaulted decisions for finance_ledger running 2026-08-21 → 2026-08-28 and then stopping dead — that stop is the fingerprint of the restore.

“Promoted” does not mean the router reads Postgres. GET /users has been a Mongo-primary read UNIONed with Postgres since identity_core was promoted. That is coexistence, not cutover — and it is the best case in the tree.

The four blockers

#BlockerMeasured
1Schema deployed, data not. Porting a route is often a data-modelling exercise, not a rewrite. 177 of 230 Postgres tables are empty. Of 153 populated Mongo collections, 13 have a populated Postgres home, 12 map to an empty table, and 128 have no Postgres target at all — including unit_levy_ledger (638 docs), which half the finance UI reads from.
2A wrong Postgres read returns zero rows silently. RLS without app.tenant_id gives count(*) = 0, no error. A ported router that forgets tenant context renders an empty dashboard that looks like a fact. Mitigated: documents_repo._require_tenant raises TenantContextMissing rather than returning empty.
3Postgres cannot yet compute a defensible per-lot finance position. paid_cents is a denormalised total; allocations are the trail saying which receipt paid which levy item. $224,733.13 of levy_items.paid_cents has no allocation row (496 items). 356 receipts / $567,813.95 unallocated. Receipts exceed charges by $338,335.05.
4The old cutover machinery is read-only by design. finance_route_cutover_service holds 37 policies, all read_only=True, 5 pg-read-supported. 0 of 614 mutating routes had any write dispatch before 2026-08-29.

The stores agree where it has been measured

The nightly DR check reports East Gate at 87/87 lots matching, $0.00 net gap, 0 payments missing from Postgres. The FY2026 unit ledger matches to the cent on both sides — Mongo 87 units, $220,187.56 levied / $212,146.26 paid; Postgres 22018756 / 21214626 cents over 87 lots.

The 260 unresolved finance_ledger shadow diffs that appeared to contradict this were comparator artefacts, fixed at source: a one-unit Mongo payload was being compared against an 87-lot Postgres aggregate, _dimension was passed by the router and never read by the comparator, and test runs were writing fixture values (12345 cents) into the production gate flagged is_test_data=False. The one dispatch seam

New code never hardcodes a store.

from services.store_router import resolve_store

decision = await resolve_store(domain="documents", building_id=building_id, operation="read")
if decision.use_postgres:
    ...        # try Postgres
...            # fall back to Mongo — always this direction, never the reverse
  • Fails closed — a domain with no control-plane row resolves to MongoDB.
  • Never raises — a blocked domain, or an unreachable control plane, degrades to Mongo with the reason attached rather than 503-ing a page.
  • mirror_to_mongo is true for every Postgres write while both stores are live. An unmirrored Postgres write destroys the DR position silently.

Reference implementation: services/documents_store.py over db_postgres/repos/documents_repo.py — the first non-finance Postgres write path in the codebase, wired into GET/POST /documents. Verified live: insert → read back → count → soft-archive → idempotent re-archive.

The coexistence union is a PHASE, not the architecture. While a domain has a Postgres table and no Postgres data, an empty Postgres result falls back to Mongo and the response says which happened — mongo_fallback_pg_empty vs mongo_fallback_pg_unavailable. Empty and unavailable are never collapsed. Delete the union once that domain's data genesis has run.

Promoting a domain

A new domain needs a readiness snapshot before it can be promoted at all: promote_domain's pre-shadow gate rejects the unknown default, and until 2026-08-29 readiness could only be set by three hardcoded functions (identity, powerhouse, financial) — so no other domain could enter the lifecycle regardless of how ready its data was. record_domain_foundation_readiness() is the generic on-ramp.

python3 scripts/cutover/promote_domain_to_postgres.py --building-id 13195 --domain documents
python3 scripts/cutover/promote_domain_to_postgres.py --building-id 13195 --domain documents --apply

--apply is a production routing change. It walks every existing gate and stops at the first refusal; it never bypasses one. Rollback: cutover_status_service.rollback_domain(...).
