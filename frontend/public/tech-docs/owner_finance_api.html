Owner Finance API

Role note: chairman is not a top-level system role — it is ec_position=CHAIRMAN on a user whose role is ec_member. Role lists on this page naming "chairman" alongside real role names are shorthand for this; see permissions.md for the full contract.

Levy breakdown, building health, and savings summary endpoints for property owners.

Overview

All owner finance endpoints are under /api/owner-finance/. They require an authenticated user with owner or higher role. Tenants receive 403 Forbidden.

All responses are scoped to the authenticated user's building_id. Owners only see data for their own building.

Allowed roles

owner, strata_admin, ec_member, strata_manager, super_admin

Corrected 2026-08-28: this list previously read chairman, which is not a top-level role — chairman is an ECPosition.CHAIRMAN value on a user whose role is ec_member (migration 0025). strata_admin was missing and is in the router's OWNER_ROLES set.

Denied roles

tenant, guest

GET /api/owner-finance/levy-breakdown

Returns the authenticated owner's quarterly levy amount broken down by budget category for the requested financial year.

Query Parameters

Param Type Default Description
unit_number string the account's own unit Unit to report on. Owner-facing pages pass the unit currently active in the sidebar unit switcher, so a multi-unit owner sees the unit they are looking at. Must be a unit the caller is actively linked to — otherwise 403 Forbidden, never a silent fallback to the default unit. A present-but-blank value is 400 Bad Request, not a fallback. Display variants resolve against the building's configured unit_display rules (87 → TH087 for East Gate). Added 2026-08-28 (GAP-IDENTITY-UNIT-SWITCH-001).

Corrected 2026-08-28: this table previously documented a year parameter. The endpoint has never accepted one — the financial year is resolved server-side and returned as data_year.

Field descriptions

Field Type Notes
your_uoe int Unit's Unit of Entitlement from units collection
total_uoe int Sum of all UOE for the building
uoe_share_pct float your_uoe / total_uoe × 100. Should be in range (0, 100).
quarterly_levy float Annual budget × uoe_share_pct / 4

balance_credit float Credit amount if negative balance (overpaid)

Grade thresholds

Grade Condition
A score ≥ 85
B score ≥ 70

D score < 55

Component status values

Status Meaning
good score_pct ≥ 80
warning score_pct ≥ 50

Data source

Data comes from the building_summaries collection. If no summary exists, health_score is null and grade is "N/A". Run POST /community-dashboard/recompute to populate.

This endpoint takes no unit_number parameter, unlike its two siblings: the figure is building-wide, so switching units must not change it. A null health_score means unmeasured and must render as "N/A" — never as 0, which would grade a building "D" on data nobody has.

GET /api/owner-finance/savings-summary

Returns the owner's share of building-wide savings for the current financial year.

Query Parameters

Param Type Default Description
unit_number string the account's own unit Same contract and same authorisation gate as /levy-breakdown above.

Response (200)

{
  "your_share_cents": 4200,
  "total_saved_ytd_cents": 185000,
  "levy_reduction_equivalent_cents": 1050,
  "your_uoe": 85,
  "total_uoe": 3847
}

Field descriptions

Field Type Notes
your_share_cents int Owner's UOE-proportional share of total savings, in cents
total_saved_ytd_cents int Total savings achieved building-wide this financial year
levy_reduction_equivalent_cents int What the savings equate to as a quarterly levy reduction

Invariant: your_share_cents ≤ total_saved_ytd_cents

Multi-Tenant Isolation

All owner-finance endpoints derive building_id from the authenticated user's JWT. Users cannot query data from other buildings — there are no building_id query parameters on these endpoints.

The unit_number parameter narrows within the caller's own units; it is not a cross-tenant or cross-owner lever. It is authorised by authorise_owner_unit() in backend/utils/unit_number.py against the session's owned_units or an active user_units link, both of which are building-scoped. An elevated role is not a bypass — manager views of another owner's ledger have their own endpoints and their own guards.

The service layer reads:

  • units (tenant-scoped) — for UOE and unit_number
  • budgets (tenant-scoped) — for annual budget categories
  • building_summaries (tenant-scoped) — for health score and components
