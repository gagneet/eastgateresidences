Jurisdictional Rule Engine — Technical Reference

Pure domain layer encoding all Australian strata statutory rules as versioned JSON data files. Eliminates inline if jurisdiction == branches from financial logic. Supports ACT, NSW, VIC, QLD.

Architecture

The engine follows a strict two-layer separation:

  • Domain layer (backend/domain/jurisdictional_rules.py) — pure synchronous Python, no DB access. Loads JSON rule files once per jurisdiction and caches them at module level. Exposes typed accessor methods.
  • Service layer (backend/services/jurisdiction_service.py) — DB-aware. Resolves a building's jurisdiction from buildings.jurisdiction and merges per-building overrides from jurisdictional_rule_overrides. Delegates all statutory rule lookups to the domain engine.

Each rule entry has this shape:

{
  "value": 10,
  "unit": "percent",
  "legislation": "UTMA 2011 s.76",
  "effective": "2011-01-01",
  "notes": "Default simple interest on unpaid levies: 10% per annum."
}

Import the module-level singleton: 

from domain.jurisdictional_rules import rule_engine
Method Return type Description
max_interest_rate_pa(jurisdiction) Decimal Statutory maximum levy interest rate per annum
interest_grace_period_days(jurisdiction) int Days before interest accrues (0 = immediate)
can_transfer_between_funds(jurisdiction) bool False for QLD (prohibited by BCCM reg 100(7))
inter_fund_transfer_resolution_required(jurisdiction) str "none" / "ordinary" / "special" / "prohibited"
overbudget_threshold_pct(jurisdiction) Decimal | None NSW = 10%; ACT/VIC/QLD = None
trust_withdrawal_authority_roles(jurisdiction) list[str] Roles authorised to initiate trust withdrawals
pooled_trust_permitted(jurisdiction) bool False for VIC and QLD
interest_belongs_to(jurisdiction) str "scheme" or "statutory_account" (NSW)
trial_balance_deadline_days(jurisdiction) int Days after AGM for trial balance (ACT=15, NSW=21)
audit_deadline(jurisdiction) str Human-readable audit deadline ("30 September", "pre-AGM")
committee_spending_cap_formula(jurisdiction) str | None "$200 * lot_count" for QLD; None for others
committee_spending_cap_per_lot_cents(jurisdiction) int | None QLD = 20000 (i.e. $200.00)
min_withholding_pct_no_abn(jurisdiction) Decimal 47% for all jurisdictions (ATO rule)
get_effective_rules(jurisdiction) dict Full rules dict (excludes _meta key) for admin display
get_meta(jurisdiction) dict Legislation name, last_reviewed date
valid_jurisdictions() list[str] ["ACT", "NSW", "VIC", "QLD"]

Passing an unknown jurisdiction raises ValueError. The engine is case-insensitive: "act" and "ACT" are equivalent.

Ownership Periods

The ownership_periods collection stores a bitemporal record of lot ownership. Each document has effective_from (mandatory) and effective_to (null = current owner). The unique compound index on (building_id, lot_id, effective_from) prevents duplicate period starts.

OwnershipService.resolve_owner(lot_id, building_id, as_at) returns the owner record active at the given datetime. This is used by the matching engine's JW name-match layer to verify payment provenance.

Adding a New Jurisdiction

  1. Create backend/domain/rules/{code}.json following the existing schema.
  2. Add the code to _VALID_JURISDICTIONS in jurisdictional_rules.py.
  3. Add tests in tests/backend/domain/test_jurisdictional_rules.py.
  4. Run migration to set buildings.jurisdiction for any existing buildings in that state.

Per-Building Overrides

A super admin can write a document to jurisdictional_rule_overrides for a jurisdiction to apply custom values. JurisdictionService.get_all_rules(building_id) merges these over the base JSON rules. Per-building overrides stored in jurisdiction_config take precedence over jurisdiction-wide overrides.

Performance Notes

  • JSON rule files are loaded once per jurisdiction and cached in the module-level _CACHE dict. No DB access occurs on any financial write path for base rule lookups.
  • The engine is thread-safe for reads (immutable cached dicts). No locking is needed.
  • Per-building override resolution does require one jurisdiction_config.find_one call; this is already on the hot path via JurisdictionService.
