Payment Matching Engine

Phase 3 – Financial Processing Overhaul | backend/integrations/matching/

Overview

The matching engine maps incoming bank transactions to open strata levies using an eight-layer pipeline. Each layer scores the best candidate lot; the engine stops at the first layer that meets or exceeds the auto-allocate threshold. Items below the threshold enter a human review queue.

Bank-feed sync and rematch entry points

POST /api/bank-feeds/sync promotes Demo Bank staged transactions into finance.bank_transactions. Each newly inserted row is dispatched to this engine as a background task. Duplicate Postgres rows are skipped by the database uniqueness rule and do not create duplicate queue items.

POST /api/bank-feeds/rematch is the backfill path for rows that already exist in finance.bank_transactions. It loads canonical Postgres rows for one account reference, rebuilds a BankTxObserved envelope, and calls match() with inbox_event_id = bank_transaction_id.

Idempotency boundary — the matching engine treats an existing inbox_event_id as an idempotent replay. Rematch reports created for new queue documents and skipped_existing for rows already represented in match_review_queue.

Eight-layer pipeline

Layers run in order. The engine stops at the first layer whose score ≥ auto_match_threshold (default 0.90). L8 always runs last as a catch-all.

# Layer name Score Signal used Default outcome
L1 ExactCRN 1.00 BPAY CRN — MOD10V05 checksum + lot lookup auto-allocated
L2 NppE2E 0.95 NPP / OSKO End-to-End Reference ID auto-allocated
L3 PartialCRN 0.90 CRN prefix substring in payment description review
L4 UnitRefAmountTiming 0.85 Unit/lot number in description + amount match + ≤30 days from due date review
L5 JWNameExactAmount 0.80 Jaro-Winkler owner-name similarity ≥ 0.88 + exact levy amount review
L6 SurnameFuzzy 0.60 Surname token-sort-ratio ≥ 80 (amount not required) review
L7 ExactAmountUnique 0.50 Exact amount matches exactly one open levy review
L8 Unidentified 0.00 Catch-all — score always 0 review
MOD10V05 CRN format — 13-digit numeric string. Scheme prefix = 0{building_id} (6 digits). Positions 7–11 = lot number (5 digits). Position 12 = instalment counter (1 digit). Position 13 = MOD10V05 check digit. Validated by validate_crn() in l1_exact_crn.py.

Agency sweep detection

Runs before the eight layers. Triggers when both conditions are true:

  1. tx.amount_cents > max(candidate.open_levy_cents for candidate in candidates)
  2. Any entity_name from the global payer_entities collection is a substring of the lowercased payment description

When triggered, match_type = "agency_sweep", best_score = 0.0, SLA window is 48 h (vs 24 h for normal items). The item goes to the review queue for manual splitting.

payer_entities is a global (non-tenant-scoped) collection. Schema:

{ bsb: str, account_number: str, entity_name: str (lowercase), entity_type: str, created_at: str }

Unique index: (bsb, account_number).

MatchingEngine API

from integrations.matching import engine

result: EngineResult = await engine.match(
    tx: BankTxObserved,
    candidates: list[LotCandidate],
    db,                          # Motor database handle
    inbox_event_id: str,         # idempotency key
    auto_match_threshold: float = 0.90,
    is_test_data: bool = False,
)

EngineResult fields

Field Type Description
queue_id str Inserted ObjectId string (None on idempotent replay)
match_type str auto | review | agency_sweep | unidentified
best_score float Highest score across all layers
best_layer str Name of the layer that produced best_score
best_lot LotCandidate | None Best candidate lot (None for agency_sweep/unidentified)
all_scores list[MatchScore] All layer results run (stops early on auto-allocate)
is_auto_allocated bool True when score ≥ threshold
is_idempotent_replay bool True when a queue doc already exists for this inbox_event_id

Idempotency

Before inserting a new queue document, the engine calls find_one({"tenant_id": ..., "inbox_event_id": ...}). If a match exists, it returns an EngineResult from the existing document without writing anything. The unique compound index (tenant_id, inbox_event_id) provides a DB-level safety net.

REST API endpoints

All endpoints are under /api/financial/matching/. Require strata_manager, strata_admin, ec_member (including an EC member holding the chairman position — chairman is not itself a role), or super_admin role. Gated by financial_integration_layer_v2 feature toggle.

Method Path Description
GET /financial/matching/queue Paginated list of queue items. Query params: status (default: pending), page, page_size. Excludes is_test_data=true records.
GET /financial/matching/queue/{item_id} Single item by ObjectId. 404 on invalid ID or not found.
POST /financial/matching/queue/{item_id}/decide Record a decision. Body: { action, lot_id?, amount_cents?, notes? }. Validates: action ∈ {allocate, reject, unidentified}; allocate requires lot_id and positive amount_cents. Emits MatchDecisionRecorded to event_log with frozen candidates_snapshot. Returns 409 if item already decided, 422 on validation failure.
POST /financial/matching/queue/bulk-decide Bounded bulk close-out for backlog clearance. Body: { action, notes, direction?, match_type?, max_items?, dry_run? }. action ∈ {reject, unidentified} only — allocate fails validation by design (bulk allocation would post to the ledger and double-count historical backfill rows). dry_run defaults to true; max_items caps at 1000 per call. Each real decision is race-guarded on status=pending, emits MatchDecisionRecorded with a shared bulk_operation_id, and records extracted_lot_code audit metadata (no candidates_snapshot is frozen on bulk decisions). See docs/runbooks/east_gate_match_queue_backlog_clearance_2026_07_03.md.
GET /financial/matching/stats Returns { queue_depth, sla_breach_count, auto_match_rate, total_last_7_days, auto_allocated_last_7_days }. Rate is computed over last 7 days; returns 0.0 when no activity.
POST /financial/matching/queue/{item_id}/promote-high-confidence Deterministic ledger promotion bypassing the generic 8-layer scoring entirely, for source_type values known to be exact by construction (synthetic_from_budget, historical_mongo — see _PROMOTABLE_SOURCE_TYPES). Requires the underlying transaction to have confidence="high" and requires_review=False; 409 otherwise. strata_web_inferred_payment transactions are deliberately never eligible here — they always carry requires_review=True regardless of confidence tier and route through the normal queue instead (GAP-FIN-015 criterion 8).
POST /financial/matching/historical-reconstruction/run GAP-FIN-015 criterion 6. Body: { from_year, to_year, dry_run? }. Synthesizes one admin+sinking demo_bank_transactions row per unit per quarter for the requested year range from annual_levies budget rates × unit UOE, tagged source_type="synthetic_from_budget". Building-agnostic (scoped to the caller's own building via get_current_building — no building_id field on the request body) and idempotent (SHA-256 idempotency key + $setOnInsert): safe to re-run. dry_run defaults true and performs zero writes. 400 if from_year > to_year; 409 if the building has no annual_levies/ units data for the range. See backend/services/historical_levy_reconstruction_service.py (importable service — also callable from scripts/migrations/migration_026_synthesize_historical_levy_payments.py, now a thin CLI wrapper around the same function).

DecideRequest schema

{ action: "allocate" | "reject" | "unidentified",
  lot_id?: str,          // required when action=allocate
  amount_cents?: int,    // required when action=allocate, must be > 0
  notes?: str }

BulkDecideRequest schema

{ action: "reject" | "unidentified",   // allocate is rejected at validation
  notes: str,                          // required, 10–2000 chars, stored on every decision
  direction?: "inflow" | "outflow",    // sign filter on tx.amount_cents
  match_type?: "unidentified" | "review" | "agency_sweep" | "auto",
  max_items?: int,                     // default 500, hard cap 1000
  dry_run?: bool }                     // default true — pass false to mutate

HistoricalReconstructionRequest schema

{ from_year: int,   // 2000-2100
  to_year: int,     // 2000-2100, must be >= from_year
  dry_run?: bool }  // default true — pass false to write demo_bank_transactions rows

Feature toggles

Key Default Purpose
financial_integration_layer_v2 disabled Enables the matching queue UI and all matching endpoints. Requires super_admin to enable.
matching_auto_allocate_enabled disabled When enabled, items at/above threshold are auto-posted to the ledger without entering the review queue. Depends on financial_integration_layer_v2.

Multi-tenant isolation

  • match_review_queue is in TENANT_SCOPED_COLLECTIONS — the TenantScopedDatabase wrapper automatically injects {"tenant_id": current_building_id} into every query.
  • payer_entities is in GLOBAL_COLLECTIONS — not scoped; accessible to all buildings.
  • The engine records tenant_id = tx.tenant_id on every queue document — even if a candidate lot belongs to a different building, the queue document is always stamped with the transaction's building.
  • Candidate scoping (ensuring only lots from the correct building are passed to the engine) is the responsibility of the caller, not the engine itself.
