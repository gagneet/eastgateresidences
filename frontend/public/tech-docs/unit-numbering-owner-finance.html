Unit Numbering & Owner Finance Resolution

Updated 2026-07-01 · branch fix/unit-finance-resolution-audit · featuretrace tag finance-owner-dashboard

Concept

Unit numbers are conceptually numeric lots. The display prefix (e.g. apartments UA, townhouses TH) is per-building presentation configuration assigned at onboarding, not data. Stored canonical keys (units.unit_number, e.g. TH087) remain the join key across finance collections until the Mongo→Postgres cutover completes; a full numeric re-key is deferred until after cutover.

Data model

StoreShape
db.settings {type: "unit_display", building_id, rules: [{prefix, min, max, pad}]}
East Gate (13195) UA lots 1–70, TH lots 71–87, pad 3
Demo Residences (UP-DEMO-001) A lots 1–14, pad 1

Seed: backend/seeds/unit_display_config.py (idempotent).

API

EndpointAuthBehaviour
GET /api/settings/unit-display Any authenticated building member Returns {building_id, rules}; empty rules = raw display.
PUT /api/settings/unit-display can_manage_users Validates prefix 0–5 letters, bounds 1–9999, pad 1–4, non-overlapping ranges (422 on violation). Display-only — never rewrites stored keys.

Handlers live inline in backend/server.py (the routers/settings.py file is an unwired mirror — endpoints added there alone return 404).

Canonical resolution in finance routes

backend/utils/unit_number.py provides:

  • unit_number_candidates(value, rules) — display variants (87, U87, Unit 87, rule-formatted) for lookup.
  • resolve_canonical_unit_number(db, building_id, value, rules) — resolves to the stored units.unit_number before authorisation and reads.
  • user_unit_matches(current_user, unit) — bidirectional ownership match across unit_number + owned_units.
  • format_unit_display(lot, rules) — numeric lot → display string.

Applied in GET /finance/unit-dashboard-overview/{unit}, unit levy history, levy status, and the owner payment write guard.

Postgres-token identity bridge

Login is Postgres-first; core.users has no unit columns. Until identity_core is promoted (see core.domain_cutover_status), get_current_user backfills unit_number, owned_units, custom_permissions, and legacy_user_id from the MongoDB user matched by email (utils/auth.py:_backfill_legacy_unit_context). Without this bridge, owner-scoped guards 403 owners on their own unit.
