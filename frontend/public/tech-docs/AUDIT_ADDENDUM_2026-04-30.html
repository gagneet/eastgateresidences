Audit Addendum — 2026-04-30

This addendum lists the differences between this static documentation set and the live application as of 2026-04-30. The HTML pages listed below are reference material that predates the Next.js App Router migration and several major schema phases. They are being refreshed in stages; until that work lands, treat the items below as authoritative.

Frontend reality

  • The frontend is Next.js App Router (React 19, NextAuth, Tailwind). Pages under frontend/src/app/(dashboard)/**/page.tsx often wrap legacy React components from frontend/src/pages/**. Both surfaces are live.
  • Shared API access and tenant context flow through frontend/src/contexts/AuthContext.tsx. Use the api instance from useAuth() — its baseURL is ${NEXT_PUBLIC_BACKEND_URL}/api, JWT auth is attached automatically, and X-Building-ID is injected on every request. Never prefix the path with /api/ when calling through this instance — that produces /api/api/... 404s.
  • Building context: super-admins switch buildings via the X-Building-ID header set by AuthContext. Direct axios imports bypass this header and produce wrong-tenant data.

Database reality

  • The live database has 176 collections (254 logical registrations) with tenant-scoped, global, and audit-derived classifications in backend/database.py. The static page database.html still cites the older "49+" figure — ignore that count.
  • Authoritative schema reference: docs/architecture/database_schema_full_2026.json.
  • plan_id is a legacy alias for building_id; new code must not write or compare plan_id directly.
  • db.settings (with building_id) holds levy/financial config. db.site_settings (id="rate_limits") is rate-limits only. Levy code that reads site_settings is a silent bug.

API reality

  • All API routes are mounted under /api via api_router in backend/server.py. Routers under backend/routers/*.py are registered with a try/except import pattern — a syntax error in a router file silently warns and skips registration.
  • Building scoping is enforced by get_current_building() in backend/utils/auth.py. Endpoints that touch tenant collections must declare building_id: str = Depends(get_current_building).
  • Role guards must use _effective_role(user) (or the inline equivalent in router files) — the raw user["role"] field is wrong for users elevated to ec_member via temporary elevation.

Deployment reality

  • The canonical production scheduler is systemd timers installed by deploy/install.sh. The legacy backend/cron/setup_cron_jobs.sh crontab installer, the in-process APScheduler in backend/workers/scheduler.py, and the ARQ Redis queue in backend/workers/arq_settings.py are secondary — used for development or queue-based work, not as primary production schedulers.
  • Backend startup creates a super-admin if none exists. This is intentional bootstrap behaviour and must not be removed.
