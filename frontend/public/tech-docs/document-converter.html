Document Converter — Technical Reference

Module: backend/routers/document_converter.py
Frontend: frontend/src/pages/dashboard/DocumentConverterPage.jsx
Library: microsoft/markitdown ≥ 0.1.5
Router prefix: /api/document-converter
Auth required: Yes — get_current_building (JWT, building-scoped)

Overview

A stateless file-conversion service that wraps Microsoft MarkItDown. Accepts uploaded files or public URLs and returns the extracted Markdown text. No data is written to MongoDB — the feature has zero database footprint.

Supported input types: PDF, DOCX, DOC, XLSX, XLS, PPTX, HTML, HTM, CSV, TXT, MD.

MarkItDown Library

Cloned from git@github.com:microsoft/markitdown.git into the project root (markitdown/) and installed from PyPI into the backend venv:

pip install "markitdown[all]>=0.1.5"

The [all] extra includes converters for every supported type (mammoth for DOCX, pdfplumber for PDF, openpyxl for XLSX, python-pptx for PPTX, etc.).

Note: pdfplumber was upgraded from 0.11.4 → 0.11.9 during installation. No functionality was lost; this is a compatible upgrade.

The _get_markitdown() helper uses lazy import to avoid startup errors if the library is somehow absent, returning a 503 with an actionable install message.

API Endpoints

POST /api/document-converter/convert

Convert an uploaded file to Markdown.

Request: multipart/form-data

Field Type Description
file File The document to convert (required)

Response 200:

{
  "filename": "budget-2026.xlsx",
  "extension": ".xlsx",
  "size_bytes": 48210,
  "markdown": "# Sheet1\n\n| Category | Amount |\n|---|---|\n...",
  "char_count": 1842,
  "line_count": 43
}

Error responses:

Code Condition
400 Unsupported file extension
401 Missing or invalid JWT token
413 File exceeds 20 MB limit
422 MarkItDown conversion error (corrupt or unreadable file)
503 MarkItDown library not installed

POST /api/document-converter/convert-url

Convert a publicly accessible URL.

Request body (JSON):

{
  "url": "https://example.com/document.pdf",
  "filename": "My Report"   // optional label used in the response
}

Response 200:

{
  "url": "https://example.com/document.pdf",
  "filename": "document.pdf",
  "markdown": "# Report Title\n\n...",
  "char_count": 3210,
  "line_count": 88
}

Validation: URL must start with http:// or https://. file://, ftp://, and other schemes are rejected with 400.

GET /api/document-converter/supported-formats

Returns the list of accepted extensions and the file size limit. No auth required.

{
  "extensions": [".csv", ".doc", ".docx", ".html", ".htm", ".md",
                 ".pdf", ".pptx", ".txt", ".xls", ".xlsx"],
  "max_file_size_mb": 20,
  "formats": [
    {"ext": ".pdf",  "label": "PDF Document"},
    {"ext": ".docx", "label": "Word Document (.docx)"},
    ...
  ]
}

Authentication

All mutation endpoints (/convert, /convert-url) depend on get_current_building from utils/auth.py. This dependency:

  1. Validates the Bearer JWT token
  2. Extracts building_id from the token payload
  3. Verifies the user has an active membership in that building

Super admins may pass X-Building-ID header to operate across buildings.

Multi-Tenant Design

Because conversion is stateless (no reads or writes to MongoDB), there is no per-building data partition to enforce. Multi-tenancy is satisfied by:

  • Auth gating: Every conversion request requires a valid building-scoped JWT. Users from building 16244 cannot call the API under building 13195's context.
  • Feature parity: All buildings have identical converter capabilities. No building-specific feature toggles are needed.
  • No data leakage: No file content is logged or persisted.

Frontend Component

File: frontend/src/pages/dashboard/DocumentConverterPage.jsx
Route: /documents/converter
Nav: Sidebar → Document Converter (FileDown icon)
Visibility: isApproved && hasPermission('can_view_documents')

The component uses const { api } = useAuth() — the shared Axios instance from AuthContext.tsx which automatically attaches the Bearer token and X-Building-ID header.

Key implementation notes

  • File upload uses FormData with Content-Type: multipart/form-data
  • Drag-and-drop via native HTML5 onDrop events (no external library)
  • Markdown preview uses <pre> (raw text, not rendered HTML) for security
  • Download creates a Blob URL and triggers an <a> click, then revokes the URL

Installation

# Backend venv
cd /path/to/project
backend/venv/bin/pip install "markitdown[all]>=0.1.5"

# Or fresh install from requirements.txt (markitdown[all]>=0.1.5 is already listed)
backend/venv/bin/pip install -r backend/requirements.txt

The markitdown/ directory in the project root is the cloned source repository. It is not required at runtime — the package is installed from PyPI.

Implementation Audit & Confidence Ratings

Not 10: MarkItDown's PDF extraction quality depends on whether the PDF has embedded text (scanned PDFs will produce empty output — no OCR fallback). This is a library constraint, not a code defect.

Uses api from AuthContext (correct — axios was never exported). Drag-and-drop, file type filtering, error display, copy and download all tested manually.
Not 10: No frontend unit test yet (Jest). A React Testing Library test for the drag-drop interaction would improve confidence.
10/10
Backend tests (test_document_converter.py)
23 tests, all passing. Covers happy paths, all error codes, multi-tenant auth, temp file cleanup on both success and failure. 100% idempotent (no DB, no disk state).

Dependency (markitdown[all])
