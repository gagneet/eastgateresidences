Demo Bank And Bank Feed Sync

Current implementation reference for Demo Bank staging, canonical bank transaction sync, and matching queue backfill.

Production tenant rule. East Gate uses real production data. Do not run sync or rematch against a live building unless the target building, account reference, feature toggles, and token context have been checked first.

Data Flow

demo_bank_transactions (Mongo staging)
  -> POST /api/bank-feeds/sync
  -> finance.bank_transactions (PostgreSQL canonical bank rows)
  -> MatchingEngine.match()
  -> match_review_queue (Mongo review queue)
  -> manager decision
  -> FinancialCoreService ledger posting

Demo Bank is not the ledger. It is a provider-simulation and evidence-staging layer. Ledger writes must still happen through FinancialCoreService after a matching decision is reviewed and approved.

Routes

Route Purpose Important behavior
POST /api/bank-feeds/sync Promote Demo Bank staged transactions to finance.bank_transactions. Idempotent via UNIQUE (trust_account_id, external_transaction_id); new rows dispatch to MatchingEngine.
POST /api/bank-feeds/rematch Replay existing Postgres bank transactions through MatchingEngine. Idempotent by inbox_event_id == bank_transaction_id; returns created and skipped_existing.
GET /api/bank-feeds/transactions List canonical bank transactions for the current building. Building scoped through authenticated context.
PATCH /api/bank-feeds/transactions/{id}/match Manually mark a canonical bank transaction as matched. This is not the historical rematch endpoint.

Auth And Building Context

  • The router is gated by financial_integration_layer_v2.
  • /sync and /rematch are additionally gated by bank_feeds_sync_enabled.
  • /sync and /rematch require super_admin or strata_admin.
  • Super-admin cross-building operations must include X-Building-ID.
  • Production calls should keep include_test_data false.

Operational Examples

curl -X POST "$API_BASE/api/bank-feeds/rematch" \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Building-ID: 13195" \
  -H "Content-Type: application/json" \
  -d '{"account_ref":"ADMIN-13195","limit":2000}'

curl -X POST "$API_BASE/api/bank-feeds/sync" \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Building-ID: 13195" \
  -H "Content-Type: application/json" \
  -d '{"account_ref":"ADMIN-13195","from_date":"2021-01-01","to_date":"2026-06-30","include_test_data":false}'

Response Fields

Endpoint Fields
/sync processed, inserted, duplicates, failed, skipped_other_batch (new 2026-07-19 — see Historical Reconstruction: non-zero only when a caller passed reconstruction_batch_id, always 0 for a normal building-wide sync)
/rematch processed, created, queued, skipped_existing, failed

East Gate Audit Result

The 2026-07-01 East Gate audit verified 2768 review queue rows after rematch plus sync for ADMIN-13195 and SINKING-13195. The queue was populated correctly, but most rows were classified as unidentified, so matching quality still depends on better payer references and levy candidate enrichment.
