Document OCR Workspace

Reference for the building-scoped OCR job workspace: upload a document, run it through a configured OCR provider, review the extracted fields, and optionally publish the raw text into the document library (GAP-OCR-001, completed 2026-07-27).

Unlimited OCR is opt-in, not on by default. Every environment ships with mock_ocr (deterministic fallback) always available. The advanced unlimited_ocr provider only becomes selectable once UNLIMITED_OCR_ENABLED=true and a backend (local GPU worker, baidu_cloud, or private_endpoint sidecar) is actually configured — most environments will only ever see auto, claude_vision, mindee, and tesseract (the existing invoice-OCR providers) plus mock_ocr here. Check GET /ocr/providers' available/unavailable_reason fields before assuming it's usable.

Data Flow

document upload (PDF/JPEG/PNG/WebP/plain text, scanned by utils.file_scan.scan_upload)
  -> POST /ocr/jobs                     (creates job, status=processing, returns immediately)
  -> [FastAPI BackgroundTasks — dispatched, never awaited inline in the request handler]
  -> ProviderRegistry.get_ocr(building_id) -> OCRProvider.extract_invoice(...)
  -> ocr_results (Mongo, building-scoped) + ocr_jobs.status updated to completed/needs_review/failed
  -> [optional] POST /ocr/jobs/{id}/publish-document -> documents (Mongo, base64 file_data)

Why background dispatch matters: the private_endpoint unlimited_ocr backend calls out to an external sidecar/cloud service with a default 20-minute timeout (UNLIMITED_OCR_TIMEOUT_SECONDS). Running that inline inside the HTTP request/response cycle would hold the connection open for the same duration and could exhaust the server's worker pool under load — create_ocr_job returns a processing job immediately via BackgroundTasks.add_task(...); the frontend polls GET /ocr/jobs/{id} every ~2 seconds (bounded to ~60s) until a terminal status is reached.

Job Status Lifecycle

  • processing — job created, extraction dispatched via BackgroundTasks, not yet finished. This is what POST /ocr/jobs always returns immediately.
  • completed — extraction finished, overall_confidence >= 0.85.
  • needs_review — extraction finished, overall_confidence < 0.85. Same data shape as completed, just flagged for a human to double-check before trusting it.
  • failed — the provider raised (unavailable, timeout, malformed response, etc.). error_code/error_message are populated; the job is never left dangling in processing forever — the background task's own try/except always reaches a terminal status.

source_type Options

Every job is tagged with one of: general_document, invoice, quote, bank_statement, agm_minutes, rates_notice, insurance, contract, maintenance_evidence. This is metadata only — it does not change which provider runs or how the result is parsed; it exists so the job list and any future per-type review workflow can filter meaningfully. Publishing to the document library currently redistributes the raw extracted text as-is for any of these types — it does not (yet) turn OCR output into a structured AGM-minutes or rates-notice record; that would be separate, larger scope.

Auth And Building Context

  • Gated on the document_ocr feature toggle (global default: enabled) plus an explicit role allowlist checked in _can_use_ocr() — broader than most finance-adjacent endpoints since OCR is a general document-parsing utility, not itself a ledger-mutating action.
  • building_id always comes from the authenticated caller's resolved building (get_current_building) — never inferred from uploaded content, never accepted from the client. Confirmed cross-building isolation: a job created for one building is invisible to GET /ocr/jobs/GET /ocr/jobs/{id} from another.
  • is_test_data (form field, defaults false) is stamped on the created job, its eventual result, and any document it's later published into — matches this repo's mandatory test-data convention. List/get endpoints exclude is_test_data=true rows.

Operational Examples

curl -X POST "$API_BASE/api/ocr/jobs" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@invoice.pdf;type=application/pdf" \
  -F "source_type=invoice" -F "provider=auto"

curl -X GET "$API_BASE/api/ocr/jobs?limit=25" \
  -H "Authorization: Bearer $TOKEN"

curl -X GET "$API_BASE/api/ocr/jobs/JOB_ID" \
  -H "Authorization: Bearer $TOKEN"

curl -X POST "$API_BASE/api/ocr/jobs/JOB_ID/publish-document" \
  -H "Authorization: Bearer $TOKEN" -F "category=ocr_extracted"
