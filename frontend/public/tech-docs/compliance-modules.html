1. Essential Services Log

GAP-COM-008  |  Router: backend/routers/essential_services.py  |  Tag: Compliance

Records compliance-driven service events for building essential services: cooling towers, HVAC, backflow prevention devices, lifts, fire pumps, emergency lighting, and exit lighting. Each entry captures the technician, company, licence number, service date, status, certificate URL, and next-due date (optionally auto-calculated from an interval).

The /overdue endpoint surfaces all entries where next_due is in the past and status is not compliant, with a computed days_overdue field.

Essential Services — API Endpoints

All endpoints require authentication. Write operations require manager roles; read operations are accessible to owners and tenants. All responses are building-scoped.

POST /api/essential-services

Log a new service event. Returns the created document with its assigned id (MongoDB ObjectId as string).

Field Type Required Notes
service_type string Yes One of the SERVICE_TYPES enum. See model below.
asset_name string Yes Human-readable label for the equipment, min 2 chars.
service_date string Yes ISO-8601 date (YYYY-MM-DD).
technician string Yes Technician full name, min 2 chars.
status string No Default: compliant. See SERVICE_STATUSES.
interval_months int No 1–120. If provided and next_due absent, auto-computes next_due = service_date + interval_months.
next_due string No ISO-8601 date. Takes precedence over interval_months if both provided.
asset_id string No Reference to building_assets._id.
company string No Contractor company name.
licence_number string No Technician licence or accreditation number.
certificate_url string No URL to the compliance certificate.
notes string No Free-text notes.
tags string[] No Optional tag list. Default: [].

Role guard: _require_manager() — super_admin, strata_manager, chairman, ec_member, admin_staff.

Errors: 400 invalid service_type, 400 invalid status, 403 insufficient role.

GET /api/essential-services

List log entries for the building (paginated, sorted by service_date DESC).

Query param Type Notes
service_type string? Filter by service type.
status string? Filter by status.
date_from string? Filter service_date >= (ISO-8601).
date_to string? Filter service_date <= (ISO-8601).
page int Default 1.
page_size int Default 20, max 100.

Role guard: _require_view() — managers + owner + tenant.

Response: { data: [...], total: int, page: int, page_size: int }

GET /api/essential-services/overdue

Returns all entries where next_due < today AND status != "compliant". Sorted by next_due ASC (most overdue first). Adds a computed days_overdue integer to each document.

Response: { data: [...], total: int, as_of: "YYYY-MM-DD" }

Note: This route is declared before /{entry_id} — FastAPI must see it first to avoid routing to the single-entry handler.

GET /api/essential-services/{entry_id}

Get a single log entry. entry_id is a MongoDB ObjectId string. Returns 400 for malformed IDs, 404 if not found or cross-building.

PUT /api/essential-services/{entry_id}

Update a log entry — typically to add a certificate URL or change status. Partial update: only provided fields are changed. Requires at least one field.

Updatable fields: status, certificate_url, next_due, notes, tags.

Role guard: manager only. Adds updated_at and updated_by.

Errors: 400 invalid status, 400 no fields to update, 404 not found.

Essential Services — Security Notes

Concern Mitigation
Building isolation All queries include building_id. TenantScopedDatabase auto-injects tenant context. Cross-building access returns 404.
Role guard Uses effective_role or role — never raw user["role"]. Handles elevated users correctly.
Read access Owners and tenants can view the log (transparency). They cannot create or modify entries.
Audit trail Every POST logs an essential_service_logged audit event to audit_logs.
Retention Records are not hard-deleted. Compliance records must be retained for the 7-year statutory period.

2. Conflict of Interest Register

GAP-GOV-007  |  Router: backend/routers/conflict_of_interest.py  |  Tag: Governance

Records conflict-of-interest declarations by EC members before agenda items are discussed. Declarations are immutable by the declarant — only managers/chairman can update the resolution field or retract (soft-delete) a record. Ties to decisions.py (decision records may reference a conflict_of_interest id) and GAP-JUR-NSW-013 (building manager disclosure).

Conflict of Interest — API Endpoints

POST /api/conflict-of-interest

Declare a conflict of interest. The authenticated user becomes the member_id. Returns the created document including its MongoDB ObjectId as id.

Field Type Required Notes
conflict_type string Yes One of: financial, personal, professional, other.
description string Yes Nature of the conflict, min 10 / max 2000 chars.
resolution string No Default: pending. See RESOLUTION_TYPES below.
related_matter string No Agenda item title or decision number.
meeting_date string No ISO-8601 date of the meeting.
notes string No Additional context.

Role guard: _require_ec() — super_admin, strata_manager, chairman, ec_member, admin_staff.

Errors: 400 invalid conflict_type, 400 invalid resolution, 403 insufficient role.

GET /api/conflict-of-interest

List declarations for the building (paginated, sorted by declared_at DESC). Retracted records are excluded by default.

Query param Type Notes
member_id string? Filter to a specific member.
conflict_type string? Filter by conflict type.
include_retracted bool Default false. Pass true to include retracted declarations.
page int Default 1.
page_size int Default 20, max 100.

GET /api/conflict-of-interest/{declaration_id}

Get a single declaration. declaration_id is a MongoDB ObjectId string. Returns 400 for malformed IDs, 404 if not found or cross-building.

PUT /api/conflict-of-interest/{declaration_id}

Update the resolution, notes, or related_matter on a declaration. Manager/chairman only. EC members cannot edit their own declarations after submission.

Updatable fields: resolution, notes, related_matter.

Role guard: _require_manager() — super_admin, strata_manager, chairman, admin_staff.

Errors: 400 invalid resolution, 400 no fields to update, 404 not found.

DELETE /api/conflict-of-interest/{declaration_id}

Soft-delete (retract) a declaration — sets retracted=True, retracted_at, and retracted_by. The document is never hard-deleted. Manager only.

Response: { message: "Declaration retracted.", declaration_id: "..." }

Conflict of Interest — Security Notes

Concern Mitigation
Building isolation All queries include building_id in the filter. Cross-building access returns 404.
Role guard Two guard levels: _require_ec() for create/view; _require_manager() for update/retract. Both use effective_role or role.
Immutability of declarations EC members cannot edit their own declarations — only managers can update the resolution field. This prevents post-hoc revision.
Soft delete only DELETE endpoint sets retracted=True; the document is never physically removed. Full audit trail is preserved.
Audit trail All create, update, and retract actions emit audit log events (conflict_declared, conflict_updated, conflict_retracted).
Test data Test-created records must carry is_test_data: true to prevent appearing in production governance views.
