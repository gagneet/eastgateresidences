Workflow Governance API

Role note: chairman is not a top-level system role — it is ec_position=CHAIRMAN on a user whose role is ec_member. Role lists on this page naming "chairman" alongside real role names are shorthand for this — including the "Role below chairman" phrasing further down; see permissions.md for the full contract.

Endpoints for workflow status, SLA overrides, and manual run triggers.

Overview

All workflow endpoints are under /api/workflows/. Most require manager-level access; the status endpoint requires at minimum ec_member.

Workflows are defined in backend/workflow_catalogue.json — a static JSON catalogue. Runtime state (last run, health) is stored in workflow_runs. SLA overrides are stored in workflow_sla_overrides.

GET /api/workflows/status

Returns the catalogue of all workflows with their current health status, last run details, and effective SLA.

Query Parameters

Param Type Description
category string (optional) Filter by category (financial, compliance, maintenance, etc.)

Required role

ec_member, chairman, strata_manager, super_admin

      "description": "Generates quarterly levy notices...",

Health status values

Value Meaning
healthy Last run succeeded within sla_hours
stale Last run succeeded but older than sla_hours
failing Last run ended with status="failure"
never_run Implemented but no run records
not_implemented In catalogue but not built yet

GET /api/workflows/{workflow_id}/sla

Returns the effective SLA for a workflow — building override if one exists, otherwise the catalogue default.

Response

{
  "workflow_id": "levy_run_quarterly",
  "building_id": "13195",
  "sla_hours": 2.0,
  "source": "override"
}

source is either "override" (building-specific) or "catalogue" (default).

PUT /api/workflows/{workflow_id}/sla

Sets a per-building SLA override for a workflow. Upserts to workflow_sla_overrides.

Required role

super_admin, strata_manager

Request body

{ "sla_hours": 2.0 }

Response (200)

{
  "workflow_id": "levy_run_quarterly",
  "building_id": "13195",
  "sla_hours": 2.0,
  "source": "override",
  "updated_at": "2026-04-01T10:00:00Z"
}

Errors

HTTP Cause
400 sla_hours is negative
403 Role below strata_manager
404 workflow_id not found in catalogue

POST /api/workflows/{workflow_id}/run

Manually triggers a workflow. Creates a workflow_runs record with trigger_type="manual" and attempts to dispatch via the workflow's implementation module.

Required role

super_admin, strata_manager, chairman

Response (200)

{
  "status": "queued",
  "run_id": "run-abc12345-...",
  "workflow_id": "levy_run_quarterly",
  "message": "Workflow queued successfully"
}

Errors

HTTP Cause
400 Workflow not implemented (returns "not_implemented" status)
403 Role below chairman
404 workflow_id not found in catalogue

Returns recent run history for a workflow.

Query Parameters

Workflow Catalogue

Located at backend/workflow_catalogue.json. Each entry:

{
  "id": "levy_run_quarterly",
  "name": "Quarterly Levy Run",
  "category": "financial",
  "trigger_type": "cron",
  "schedule": "0 8 1 */3 *",
  "trigger_description": "...",
  "description": "...",
  "sla_hours": 4,
  "implemented": true,
  "module": "workflows.levy_run",
  "function": "run",
  "required_artefacts": ["unit_levy_ledger", "budgets"],
  "failure_mode": "Alert EC and retry next day",
  "jurisdiction_notes": "..."
}

When implemented: true, the POST /run endpoint imports module and calls function(building_id) via asyncio.
