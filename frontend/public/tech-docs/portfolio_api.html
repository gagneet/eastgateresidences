Portfolio API

Role note: chairman is not a top-level system role — it is ec_position=CHAIRMAN on a user whose role is ec_member. Role lists on this page naming "chairman" alongside real role names are shorthand for this; see permissions.md for the full contract.

Endpoints for cross-building portfolio metrics and building health.

Overview

All portfolio endpoints are under /api/portfolio/ and require a manager-level JWT (super_admin, strata_manager, or chairman). Owners and tenants receive 403 Forbidden.

Data is sourced from:

  • buildings collection — building metadata (name, lots, ID)
  • building_summaries collection — computed health scores and metrics
  • maintenance_requests — open work order counts
  • unit_levy_ledger — arrears rate calculation

GET /api/portfolio/summary

Portfolio-wide aggregated totals across all buildings.

Required role

super_admin, strata_manager, chairman

Response

{
  "active_buildings": 3,
  "total_lots": 294,
  "total_arrears_cents": 1523000,
  "avg_building_health": 74.0,
  "open_work_orders": 12
}

Fields

Field Type Description
active_buildings int Number of active buildings in the portfolio
total_lots int Sum of lot_count across all buildings
total_arrears_cents int Total outstanding levy amounts in cents (from unit_levy_ledger)
avg_building_health float Mean health_score from building_summaries (0–100)
open_work_orders int Total open maintenance_requests across all buildings

GET /api/portfolio/dashboard

Per-building rows with health scores, arrears rate, open work orders, and next compliance item.

Required role

super_admin, strata_manager, chairman

Response

{
  "buildings": [
    {
      "building_id": "99001",
      "name": "Harbour View Apartments",
      "lot_count": 87,
      "health_score": 74,
      "grade": "B",
      "arrears_rate": 3.2,
      "open_work_orders": 5,
      "next_compliance_item": "Fire safety inspection — Jul 2026",
      "last_computed_at": "2026-04-01T02:00:00Z",
      "has_data": true
    }
  ],
  "summary": {
    "total_buildings": 3,
    "total_lots": 294,
    "avg_health_score": 74.0,
    "alert_count": 0
  },
  "alerts": []
}

Building row fields

Field Type Notes
building_id string Unit plan number e.g. "13195"
lot_count int Falls back to bld.get("lots", 0) for legacy records
health_score int | null null if building_summaries not yet computed
grade string | null A/B/C/D or null
arrears_rate float % of lots with outstanding levies
open_work_orders int Count of maintenance_requests with status != "completed"/"closed"
next_compliance_item string | null From building_summaries.next_compliance_item
has_data bool true if building_summaries record exists
last_computed_at ISO8601 | null When _compute_summary() last ran

Alerts

An alert is added when health_score < 50:

{ "type": "low_health", "building_id": "13195", "value": 40 }

GET /api/portfolio/users/search

Search existing users for building assignment (strata manager or EC committee member selection).

Required role

super_admin, strata_manager

Query parameters

Param Type Description
role string (optional) Filter by role — must be one of the platform's valid role values or 422 is returned
query string (optional) Full-text search on full_name and email (regex, case-insensitive)

Response

[
  {
    "id": "u-abc123",
    "full_name": "Jane Smith",
    "email": "jane@firm.com.au",
    "role": "strata_manager",
    "is_active": true
  }
]

Maximum 50 results. Credential and PII fields (password, totp_secret, home_address, phone numbers, etc.) are explicitly excluded from the projection.

Error responses

HTTP Cause
403 Role is not super_admin or strata_manager
422 role param is not in the valid role allowlist

POST /api/admin/onboarding/scheme

Start a new scheme onboarding session for an SM organisation tenant. This is the supported admin entrypoint for the legacy building setup flow.

Required role

super_admin, strata_admin, strata_manager

Request body

{
  "tenant_id": "ten_123",
  "scheme_number": "UP99001",
  "scheme_name": "Harbour View Apartments",
  "jurisdiction": "ACT",
  "legal_name": "The Owners - Units Plan 99001",
  "abn": "12345678901" // optional
}

Response (201 Created)

{
  "session_id": "ons_123",
  "tenant_id": "ten_456",
  "scheme_id": "sch_456",
  "status": "started",
  "current_step": 1,
  "step_data": {},
  "created_at": "2026-05-04T09:30:00Z",
  "updated_at": "2026-05-04T09:30:00Z",
  "message": "Onboarding session started for scheme UP99001."
}

Validation rules

  • tenant_id, scheme_number, scheme_name, and jurisdiction are required
  • Super admins must supply tenant_id; strata_admin and strata_manager callers use their own tenant context
  • The scheme number must be unique within the jurisdiction
  • Self-managed tenants cannot create a second scheme

Side effects

  • Creates or resumes an onboarding session for the target SM organisation
  • Creates the scheme record when the session is first started
  • Routes follow-up detail work through /api/admin/sm-organisations/{tenant_id} endpoints

Error responses

HTTP Cause
400 building_id cannot be derived from unit_plan_number (e.g. all special chars)
403 Role is not super_admin or strata_manager
409 Building with derived building_id already exists
422 No CHAIRMAN in ec_members, or missing required fields

DELETE /api/portfolio/buildings/{building_id}

Soft-archives a building. All data is retained for audit and compliance (7-year minimum). The building is hidden from all normal views. Super Admin only.

Required role

super_admin

Request body (optional JSON)

Field Type Description
reason string? Optional reason for archiving (recommended for audit trail)

Side effects

  • Sets is_archived=true, is_active=false, archived_at, archived_by, archived_reason on the building document
  • Soft-archives all associated memberships, building_invitations, building_onboarding_checklists, ec_members records for this building
  • Creates an audit log entry with action="building_archived"

Response

204 No Content on success.

Error responses

HTTP Cause
403 Role is not super_admin
404 Building not found
409 Building is already archived

POST /api/portfolio/buildings/{building_id}/revive

Revives an archived building, restoring it to active status. Also restores associated memberships and EC member records. Super Admin only.

Required role

super_admin

Side effects

  • Clears is_archived, sets is_active=true, records revived_at and revived_by
  • Restores only previously-archived memberships, building_invitations, and ec_members records (scoped to is_archived=true)
  • Creates an audit log entry with action="building_revived"

Response (200 OK)

Returns the updated building document with revive fields set.

Error responses

HTTP Cause
403 Role is not super_admin
404 Building not found
409 Building is not currently archived

GET /api/portfolio/buildings/archived

Lists all archived buildings with archive metadata. Intended for the Super Admin buildings management page. Super Admin only.

Required role

super_admin

Response

{
  "buildings": [
    {
      "id": "99001",
      "building_id": "99001",
      "name": "Harbour View Apartments",
      "address": "1 Performance Test Street",
      "is_archived": true,
      "is_active": false,
      "archived_at": "2026-04-19T00:00:00+00:00",
      "archived_by": "u-sa-001",
      "archived_reason": "Strata management transferred"
    }
  ],
  "total": 1
}

Notes

  • Results are sorted by archived_at descending (most recently archived first)
  • Maximum 500 records returned

Data Dependencies

building_summaries collection

Health scores are not computed on-the-fly. They must be pre-computed by calling POST /community-dashboard/recompute or running the seed script:

cd backend
venv/bin/python3 -c "
import asyncio, sys
sys.path.insert(0, '.')
from seeds.seed_building_summaries import seed_building_summaries
asyncio.run(seed_building_summaries())
"

lot_count field

The buildings collection may store lots as either lot_count (new) or lots (legacy). All portfolio endpoints use bld.get("lot_count", bld.get("lots", 0)) to handle both.

Error Responses

HTTP Cause
401 Missing or invalid JWT
403 Role is owner or tenant — manager role required
500 MongoDB query error — check backend logs
