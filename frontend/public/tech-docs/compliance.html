Compliance Modules

The compliance suite covers seven statutory obligation areas for strata management in the ACT and NSW. Each module is a separate FastAPI router in backend/routers/ with its own MongoDB collections, permission guards, and audit trail. All endpoints are building-scoped via building_id.

Legislative scope. This platform operates primarily under the ACT Unit Titles (Management) Act 2011 (UTMA 2011) for East Gate Residences (building 13195, Denman Prospect, ACT). NSW legislation (Strata Schemes Management Act 2015) applies to Sierra (16244) and Harbourview demo buildings. The WHS Act 2011 (Cth) applies nationally.

1. Rental Certificates — ACT s.119A

ACT Unit Titles (Management) Act 2011 s.119A requires that an owners corporation issue a certificate of title information before any lot can be leased or rented. The certificate discloses levy amounts, arrears, EC membership, and outstanding by-law issues to the prospective tenant or their agent.

Router: backend/routers/rental_certificates.py  |  Collection: rental_certificates

Feature toggle key: rental_certificates

Workflow

sequenceDiagram participant O as Owner participant API as API participant EC as EC/Admin participant DB as MongoDB O->>API: POST /rental-certificates API->>DB: Insert {status: "requested"} API->>EC: Email notification (all manage roles) EC->>API: PUT /rental-certificates/{id}/issue API->>DB: Read units, annual_levies, unit_levy_ledger, ec_members API->>DB: Auto-populate financial snapshot API->>DB: Supersede previous ISSUED certs for same unit API->>DB: Update {status: "issued", expiry_date: +5yr} API->>O: Email "certificate ready" O->>API: GET /rental-certificates/{id}/pdf API-->>O: StreamingResponse (PDF bytes)
Rental certificate lifecycle — request → issue → download

Auto-Population on Issue

When PUT /rental-certificates/{id}/issue is called, _auto_populate_financial_data() queries four collections in parallel to build the financial snapshot embedded in the certificate:

# _auto_populate_financial_data() sources
db.units              → owner_name, lot_number, unit_entitlement, property_type
db.annual_levies      → levy_annual, levy_quarterly, admin_budget_current, sinking_fund_balance
db.unit_levy_ledger   → arrears_amount (net_balance, most recent year)
db.ec_members         → ec_members_snapshot (name + role, up to 20 members)

Auto-Supersede Behaviour

When a new certificate is issued for a unit, all previous issued certificates for that unit are atomically set to superseded. This ensures only one active certificate exists per unit at any time.

await db.rental_certificates.update_many(
    {"unit_number": unit_number, "status": "issued", "id": {"$ne": cert_id}},
    {"$set": {"status": "superseded", "updated_at": now_str}},
)

PII Masking (Impersonation)

When a super_admin accesses a certificate while impersonating another user (impersonator_id is present in the JWT), _cert_doc_to_response(is_impersonated=True) masks tenant_name, owner_name, requested_by_name, issued_by_name, and all ec_members_snapshot names with REDACTED.

PDF Generation

Called via utils.pdf_generator.generate_rental_certificate_pdf(doc, building_name). Returns a bytes object that is streamed to the client as application/pdf with filename {cert_number}.pdf. Relies on ReportLab. Only available when status == "issued".

2. Work Health & Safety (WHS) Compliance

Implements obligations under the Work Health and Safety Act 2011 (Cth) and WHS Regulation 2017 for contractor management and safety incident reporting within the strata scheme.

Router: backend/routers/whs.py  |  Prefix: /whs

Collections: whs_inductions, whs_swms, whs_incidents

Permission Guard

_ALLOWED_ROLES = {
    "super_admin", "strata_manager", "building_admin",
    "ec_member", "admin", "maintenance"
}

All WHS endpoints require one of these roles. Standard owners/tenants cannot access WHS records.

Tracks site inductions for every contractor working on the property. Inductions expire after 365 days by default and must be renewed before work resumes.

2.2 Safe Work Method Statements (SWMS)

Under WHS Regulation 2017 r.291, a SWMS must be prepared before any high-risk construction work commences. This module stores and tracks SWMS records for each job.

Method Path Description
POST /whs/swms Create a SWMS record
GET /whs/swms List SWMS records (paginated). Filter: ?status=approved&high_risk_only=true
PUT /whs/swms/{id} Update SWMS (e.g. approve, mark superseded)
High-risk SWMS flag. When high_risk_work=true, the system adds a mandatory note to the record: "HIGH-RISK CONSTRUCTION WORK — A SWMS must be prepared before work commences (WHS Regulation 2017 r.291)." The dashboard tracks unapproved high-risk SWMS as a critical compliance issue.

SWMS Status Values

draft → reviewed → approved / expired / superseded

2.3 Safety Incidents

Logs workplace incidents, near-misses, and dangerous incidents in compliance with WHS Act 2011 ss.35–38 (notifiable incidents).

Method Path Description
POST /whs/incidents Log an incident or near-miss
GET /whs/incidents List incidents. Filter: ?incident_type=near_miss&investigation_status=open

Incident Types & Notification Rules

Type Auto-flag Legislation
near_miss No Internal record only
injury No (unless notified_authority=false) WHS Act s.35
property_damage No Internal record only
environmental No Internal record only
dangerous_incident Yes — sets authority_notification_required=true WHS Act s.38 — must report to regulator immediately

When incident_type == "dangerous_incident" and notified_authority == false, the system adds a notification flag and the dashboard surfaces it as a critical issue requiring immediate action.

2.4 WHS Dashboard

GET /whs/dashboard — Returns a consolidated compliance summary. Implemented with three parallel MongoDB $facet aggregations for minimal latency:

# Response shape
{
  "building_id": "13195",
  "as_at": "2026-04-02T...",
  "compliant": true,           // false if any critical issues
  "inductions": {
    "total": 12, "current": 9, "expired": 2, "pending_renewal": 1,
    "expiring_in_30_days": [{"contractor_name": "...", "days_until_expiry": 14}]
  },
  "swms": { "total": 5, "draft": 1, "approved": 4, "high_risk_unapproved": 0 },
  "incidents": { "total": 3, "open": 1, "authority_notification_pending": 0 },
  "issues": [{"severity": "warning", "message": "2 inductions have expired."}]
}

The compliant flag is false only when there are critical severity issues (unapproved high-risk SWMS or pending authority notification). Warnings (expired inductions, open investigations) do not affect compliance status.

3c. Initial Maintenance Schedule (GAP-JUR-NSW-005)

Legislation: NSW Strata Schemes Management Act 2015 s.80 + Schedule 3. The owners corporation must prepare an initial maintenance schedule (IMS) for all common property at or before the first AGM (or within 6 months of registration). The schedule must be reviewed at every subsequent AGM. Penalty: up to $5,500 per offence. Record retention: 7 years.
