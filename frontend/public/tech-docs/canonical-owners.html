A call graph answers what calls what. It cannot answer does this concept already have an owner? — a re-implementation creates no edge to the original, so every map renders it as healthy new code. How to add an entry: name the concept, pick one owner module, list the symbols callers use, write a reviewer-applicable rule, cite the incident/risk, add a precise detector, and record exact existing debt only.

Whether a manager's function covers a part of the product is answered once, by manager_function_service. A route declares its SURFACE via route_guards.require_manager_surface and never inspects appointment_type, management_entities.function_scoping_enabled, or a local surface list itself.

Enforced by

Why one owner

This layer only ever REMOVES access, so a second implementation does not fail loudly the way a duplicated role check does - it silently narrows differently, or forgets to narrow at all, and looks identical to an agency that has not opted in. The four rules that make it safe (off by default, no appointment means full scope, engagement beats function, fail open with a logged reason) are decisions, not arithmetic: a re-derivation gets one of them wrong.
