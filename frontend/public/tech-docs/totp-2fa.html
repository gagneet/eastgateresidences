TOTP Two-Factor Authentication

Time-based OTP 2FA — P0-02

Overview

TOTP 2FA (RFC 6238) is implemented via the pyotp library. Secrets are stored encrypted in MongoDB using the existing ENCRYPTION_KEY Fernet scheme. Backup codes are hashed with bcrypt.

Soft enforcement: accounts without totp_enabled=True continue to log in normally.

Files

  • backend/routers/totp.py — All TOTP endpoints
  • backend/models/user.py — totp_enabled, totp_verified_at fields added to UserResponse
  • backend/utils/crypto.py — encrypt_sensitive/decrypt_sensitive helpers
  • tests/backend/test_totp.py — 17 unit tests

Endpoints

Method Path Description
POST /api/auth/totp/setup Generate secret + QR code (does not enable)
POST /api/auth/totp/verify Verify code and enable 2FA
GET /api/auth/totp/status Current 2FA state for authenticated user
POST /api/auth/totp/disable Disable 2FA (requires valid code)
POST /api/auth/totp/challenge Exchange totp_pending token + code for full JWT

Database Schema

Added to each user document in MongoDB:

{
  "totp_enabled": false,           // boolean — default false
  "totp_verified_at": null,        // ISO timestamp — set when enabled
  "totp_secret_encrypted": "enc:…", // Fernet-encrypted base32 secret
  "totp_backup_codes_hashed": []   // list of bcrypt hashes
}

Login Flow Integration

When a user with totp_enabled=True logs in, the login endpoint responds with:

{
  "status": "totp_required",
  "totp_token": "eyJ…"  // short-lived JWT (type=totp_pending, exp=5min)
}

The NextAuth auth.ts authorize callback detects status === "totp_required" and stores the totp_token in the NextAuth session (session.totp_required = true, session.totp_token = <pending JWT>). The LoginPage.jsx then reads the session and redirects to the TOTP challenge page (/login/totp-challenge).

On the challenge page (frontend/src/app/(public)/login/totp-challenge/page.tsx), the user enters their 6-digit authenticator code (or a backup code). The page calls POST /api/auth/totp/challenge with the totp_token and code. On success, a full session JWT is returned and the user is redirected to /dashboard.

Secret Storage

Secrets are encrypted with the existing ENCRYPTION_KEY from config.py (Fernet) via utils/crypto.py → encrypt_sensitive(). This is the same key used by the Asset Register — no new key management needed.

Backup codes are hashed with bcrypt (cost factor 12) and stored as a list of hashes. The plain-text codes are shown once on setup and never persisted.
