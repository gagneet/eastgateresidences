Seed Reference

Role note: chairman is not a top-level system role — it is ec_position=CHAIRMAN on a user whose role is ec_member. Role lists on this page naming "chairman" alongside real role names are shorthand for this; see permissions.md for the full contract.

Seed files populate MongoDB collections with initial data. All seeds live in backend/seeds/. The orchestrator entry point is backend/seeds/seed_all.py.

Overview

There are two categories of seed file with very different operational rules:

Type A — Snapshot Seeds

Generated from the live production database using scripts/db/snapshot_all.py. They capture the authoritative state of production collections at a point in time.

  • Do not edit manually — regenerate from the live DB
  • East Gate (13195) financial data is read-only — never overwrite
  • Named with the snapshot_ prefix or are the source-of-truth unit files

Type B — Idempotent Creator Seeds

Use upsert logic — safe to run on any environment including fresh installs. Running them multiple times has no adverse effect.

  • Safe to run in any order after Type A snapshots
  • Demo buildings (Sierra, Harbourview) use these exclusively
  • CI/CD pipelines should use these (not snapshots of East Gate financial data)

Production Data Protection

CRITICAL — NEVER overwrite these collections for building 13195.

The following collections contain real production financial data for East Gate Residences. They are the source of truth for levy calculations, owner statements, audit trails, and trust accounting. Overwriting them — even with a "fresh" reseed — can corrupt financial records, break levy calculations, and affect real owners' account balances.

  • unit_levy_ledger — per-unit per-year financial ledger (all payments, balances, opening arrears)
  • annual_levies — FY2021–2026 approved levy schedules and UOE totals
  • levy_payments — individual payment records (date, amount, method, reference)
  • finance — financial transactions (income, expense entries, reconciliation data)
  • trust_ledger_entries — double-entry journal for trust accounting

Restore from backup if these are accidentally overwritten:

ls ~/backups/mongodb/
mongorestore --uri="$MONGO_URL" --db="$DB_NAME" ~/backups/mongodb/latest/

How Well-Behaved Seeds Protect Production Data

# Pattern A — skip if East Gate collection is already populated
count = await db.unit_levy_ledger.count_documents({"building_id": "13195"})
if count > 0:
    print("Skipping — East Gate levy ledger already populated")
    return

# Pattern B — upsert (setOnInsert) — safe for config collections
await db.feature_toggles.update_one(
    {"key": toggle["key"], "building_id": toggle["building_id"]},
    {"$setOnInsert": toggle},   # only inserts if not already present
    upsert=True,
)
