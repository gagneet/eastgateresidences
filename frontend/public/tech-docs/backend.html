Backend Architecture

The backend is a FastAPI application with an async MongoDB driver (Motor). Originally a single-file monolith, it has been modularised into 23 feature-specific routers. Auth is fully consolidated into routers/auth.py — the single source of truth for all authentication logic.

Entry Point — server.py

backend/server.py (~11,370 lines) is the main application file. It:

  • Creates the FastAPI app instance with CORS and slowapi rate-limiting middleware
  • Connects to MongoDB via Motor AsyncIOMotorClient
  • Registers all 23 sub-routers under the /api prefix (including auth_router)
  • Contains inline endpoints not yet extracted to routers
  • Exposes utility functions shared by routers (get_current_user, send_email_async, hash_password, verify_password, create_token) 
# server.py — simplified structure
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from motor.motor_asyncio import AsyncIOMotorClient
from utils.rate_limit import limiter, SLOWAPI_AVAILABLE

app = FastAPI(title="East Gate Residences Strata Management")
app.add_middleware(CORSMiddleware, allow_origins=CORS_ORIGINS, ...)

# Rate limiting middleware (slowapi)
# Set DISABLE_RATE_LIMIT=1 in .env to bypass all slowapi enforcement (dev/test only).
if SLOWAPI_AVAILABLE:
    from slowapi import _rate_limit_exceeded_handler
    from slowapi.errors import RateLimitExceeded
    app.state.limiter = limiter
    app.add_exception_handler(RateLimitExceeded, _rate_limit_exceeded_handler)

# MongoDB connection

db = client[DB_NAME]

# Include all routers
api_router = APIRouter(prefix="/api")
from routers.auth import router as auth_router

Pydantic Models

All request/response shapes are defined as Pydantic models in backend/models/. FastAPI automatically validates incoming JSON and serialises responses.

No migrations needed. MongoDB is schema-flexible. Pydantic validates at runtime. To add a field: add it to the model and restart the backend. 
# Example model pattern (models/finance.py)
from pydantic import BaseModel
from typing import Optional
from datetime import datetime

class AnnualLevy(BaseModel):
    id: str
    year: str
    plan_id: str
    total_uoe: int
    status: str  # "proposed" | "actual"
    admin_fund: FundData
    sinking_fund: FundData
    created_at: str  # ISO 8601
    updated_at: str

class AnnualLevyResponse(AnnualLevy):
    # Extra computed fields returned in API responses
    admin_levy_per_uoe_annual: float
    sinking_levy_per_uoe_quarterly: float

Utility Layer

utils/auth.py

  • hash_password(pwd) — bcrypt hash
  • verify_password(plain, hashed) — bcrypt verify
  • create_access_token(data) — HS256 JWT, 24h expiry
  • decode_token(token) — JWT decode + validate
  • get_current_user(token) — FastAPI Depends() helper

utils/permissions.py

  • check_permission(user, perm) — raises 403 if denied
  • is_admin(user) — super_admin or building_admin
  • is_manager(user) — admin, building_admin, strata_manager
  • transform_user_response(user) — clean sensitive fields

utils/email.py

  • Multi-provider: Resend → SMTP → SendGrid fallback
  • send_email_async(to, subject, html)
  • Port 465 → SMTP_SSL (implicit TLS)
  • Port 587 → SMTP + STARTTLS
  • Logs sent/failed counts

utils/pdf_generator.py

  • Uses ReportLab to build PDFs in memory
  • Returns BytesIO stream for FastAPI StreamingResponse
  • Templates for: Purchase Orders, Invoices, Financial Reports

utils/finance_helpers.py

  • Levy calculation per unit (UOE-weighted)
  • Budget vs actual variance
  • compute_period_due_dates() — generates period due-date list from site settings
  • get_arrears_unit_count() — units in arrears for a given year
  • get_arrears_total_amount() — total outstanding arrears (grace-period-aware)
  • get_arrears_metrics() — canonical per-unit, grace-aware arrears; delegates to domain/finance/formulas/arrears.py::unit_arrears_and_credit(). Arrears is per-unit; a credit on one unit never nets against another unit's arrears.
  • get_collection_rate_metrics() — canonical Due-date Collection Rate; delegates to domain/finance/formulas/collection.py::due_date_collection_rate(). Distinct from full-year levy coverage / fund health; also returns Collected-in-Advance.
  • sum_ledger_collected_outstanding() — building rollup with no cross-unit netting.
  • get_latest_levy_year() / get_latest_ledger_year() — resolves current FY
Calculation singularity (GAP-FIN-040): exactly one backend implementation per financial concept; every router/page calls these helpers. Enforced by tests/backend/test_finance_calculation_singularity_guardrail.py, which fails the build if arrears is derived from a raw net_balance > 0 aggregate, or if balance_owing/total_closing/strata_web_balance are read for arrears outside the canonical helpers. Due-date Collection Rate, Full-Year Levy Coverage / Fund Health, and Collected in Advance are three distinct, never-conflated metrics.

utils/helpers.py

  • Notification creation helper
  • Activity log writer
  • UUID generation
  • Date/time utilities

How to Add a New Endpoint

  1. Create/update a Pydantic model in backend/models/ for request/response shapes.
  2. Add the route function to the appropriate router in backend/routers/. Use Depends(get_current_user) for auth.
  3. Add permission check with check_permission(current_user, "can_...") if needed.
  4. Query MongoDB via db.collection_name.find_one() or find() (all async with await).
  5. Verify the router is imported in server.py — most routers are already registered.
  6. Restart the backend: sudo systemctl restart eastgate-backend
# Step-by-step example
# 1. Model in backend/models/example.py
class ExampleCreate(BaseModel):
    name: str
    value: float

class ExampleResponse(BaseModel):
    id: str
    name: str
    value: float
    created_at: str

# 2. Route in backend/routers/example.py (or add to existing router)
@router.post("/examples", response_model=ExampleResponse)
async def create_example(
    data: ExampleCreate,
    current_user = Depends(get_current_user)
):
    check_permission(current_user, "can_manage_finances")  # or appropriate perm
    doc = {
        "id": str(uuid.uuid4()),
        "name": data.name,
        "value": data.value,
        "created_at": datetime.utcnow().isoformat()
    }
    await db.examples.insert_one(doc)
    return doc

Next Estimated Payment Algorithm

The next_payment_adjusted field on OwnerUnitResponse is computed in server.py for both GET /owners-units (list) and GET /owners-units/{unit_number} (single). It uses a unified formula that handles all carry-forward scenarios without special-casing.

Inputs

Variable Source Semantics
effective_total_paid max(ledger.total_paid, direct_payments_sum) All confirmed in-year payments
opening_arrears ledger.admin_opening + ledger.sinking_opening Negative = prior-year credit; Positive = prior-year debt
period_levy annual_levy / payments_per_year Levy amount per instalment period
due_dates compute_period_due_dates() from site settings List of ISO date strings for each period

Formula

net_credit     = effective_total_paid − opening_arrears
periods_funded = floor(max(0, net_credit) / period_levy)
outstanding    = (periods_funded + 1) × period_levy − net_credit

net_credit is a single signed number that absorbs both credits (negative opening_arrears) and arrears (positive opening_arrears) from the prior year, together with all confirmed in-year payments.

Decision Logic

Condition next_payment_adjusted next_due_date
periods_funded ≥ len(due_dates) 0.00 — fully paid null
Current period due date + 14 days ≥ today (within grace) outstanding due_dates[periods_funded]
Current period due date + 14 days < today (overdue) period_levy + outstanding — arrears roll into next period due_dates[periods_funded + 1]
Overdue AND this is the last period outstanding (just the arrears) null

Examples (period_levy = $1,400, Q1 due 31 Mar, grace expires 14 Apr)

opening_arrears paid net_credit outstanding Before grace After Q1 grace
−$200 (credit) $1,000 $1,200 $200 $200 / Mar 31 $1,600 / Jun 1
+$200 (arrears) $600 $400 $1,000 $1,000 / Mar 31 $2,400 / Jun 1
$0 $1,800 $1,800 $1,000 (Q2) $1,000 / Jun 1 $2,400 / Sep 30
$0 $5,600 $5,600 — $0 (fully paid) $0 (fully paid)

Frontend Display

FinancialSummaryCard.jsx shows a contextual sub-label beneath the payment amount:

Critical Fixes — 2026-03-12

MongoDB Upsert Double-Field Error (Code 54)

MongoDB 6.0 raises WriteError: cannot infer query fields to set, path 'X' is matched twice when the same field appears in both the upsert filter and the $set document. This caused 500 errors on GET /api/intelligence/levy-fairness and GET /api/intelligence/capital-shock.

Fix pattern: Exclude filter-key fields from $set:

update_doc = {k: v for k, v in result.items() if k != "building_id"}
await db.foo.update_one({"building_id": bid}, {"$set": update_doc}, upsert=True)

Files fixed: services/capital_shock_service.py, services/levy_fairness_service.py (3x), services/building_stress_service.py, routers/intelligence.py, routers/council_rates.py, routers/finance.py, routers/analytics.py, routers/notifications.py, routers/security.py, routers/market.py.

ZeroDivisionError in Levy Fairness Engine

simulate_levy_fairness_v2 divided by actual_total=0 when levy ledger is empty. Fixed: divisor defaults to 1.0 when actual_total < 0.01.

Security: File Upload Path Traversal & Type Spoofing

POST /tenant/maintenance/upload-photo had two vulnerabilities:

  1. Path traversal: request_id used unsanitised in directory path. Fixed: stripped to 24 lowercase hex chars; directory resolved and validated within UPLOAD_BASE.
  2. Content-type spoofing: Only startswith("image/") checked. Fixed: exact allowlist {image/jpeg, image/png, image/gif, image/webp, image/heic} + extension validation.

Date Calculation Bug (OwnerHub 6-Month Lookback)

now_dt.replace(month=…) raised ValueError for end-of-month dates (e.g. Mar 31 → Sep 31). Fixed: always use day=1 when replacing month.

API Prefix Double-Slash Fix

OwnerHub and related pages used api.get('/api/owner-hub/…') but Axios already has baseURL=/api → requests hit /api/api/… (404). Fixed in 8 files.
