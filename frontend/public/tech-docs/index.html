How to Use This Documentation

👩‍💻 Developers

  • Start with Architecture for system overview
  • Use API Reference and Swagger UI for endpoint details
  • See Backend for adding new endpoints
  • See Frontend for adding new pages

🏛️ Architects

  • Architecture has system design diagrams
  • Database has ER diagrams and schemas
  • Mind Maps map every router → collection → UI page
  • Architecture Console for a live clickable graph
  • Workflows shows key business processes
  • Auth details the security model

📊 Business Analysts

  • Workflows maps all business processes
  • Permissions shows role-capability matrix
  • Frontend Pages lists all user-facing screens
  • Feature toggles control rollout of features; the current seed registry contains 179 entries

🗄️ DBAs

  • Database documents the current Mongo/Postgres data model and tenant scoping rules
  • Seeding scripts in backend/seeds/ — see Seed Reference
  • No migrations — Pydantic runtime validation + MongoDB flexible schema
  • All tenant collections require building_id in every query

📋 Product Managers

  • Frontend Pages lists all 74 screens
  • Workflows maps user journeys
  • 63 feature toggles for controlled rollout
  • Role matrix shows access by role

🚀 DevOps

  • Deployment covers all env vars and scripts
  • systemd service for backend process management
  • React build output served as static files
  • Testing covers CI integration
