Smart Requests Workflow — Tech Docs

Covers the full request lifecycle: intake classification, auto-resolution, staff triage, status management, SLA tracking, and notification dispatch.

Architecture Overview

Two routers handle requests. Both share the same workflow_requests MongoDB collection:

Router Prefix Purpose
routers/workflow_requests.py /api/workflow-requests CRUD, status updates, structured create
routers/engagement.py /api/engagement Smart intake, triage queue, stats, morning card, building pulse

Classification and auto-resolution logic lives in backend/services/comms_intake_service.py. Data models are in backend/models/community_os.py.

Feature Toggle

Smart Requests require the smart_requests feature toggle to be enabled for the building. Endpoints guarded by this toggle return 403 when disabled.

API Endpoints

Workflow Requests Router

Method Path Auth Description
POST /workflow-requests/smart Any authenticated user Submit a smart intake request. Triggers classification + optional auto-resolution.
POST /workflow-requests/ Any authenticated user Create a structured request (explicit request_type required).
GET /workflow-requests/ Any authenticated user List requests. Residents see only own requests; staff see all building requests.
GET /workflow-requests/{request_id} Owner or staff Get full request document.
GET /workflow-requests/{request_id}/status Owner or staff Get status + activity timeline (from audit_logs).
PUT /workflow-requests/{request_id}/status Staff only Update status, assign to staff member, add resolution notes.
GET /workflow-requests/stats/triage Staff only Triage ROI stats: auto-resolved today, deflection rate, weekly volume.

Engagement Router

Method Path Auth Description
POST /engagement/requests/smart Any authenticated user Alternate smart intake endpoint (same service as above).
GET /engagement/requests Any authenticated user List requests (role-scoped).
GET /engagement/requests/{request_id}/status Owner or staff Status + timeline.
GET /engagement/triage Staff only Triage queue: overdue, needs-review, due-soon buckets.
GET /engagement/stats Staff only Deflection rate, SLA breach count, human-handled count (7-day window).
GET /engagement/morning-card Any authenticated user Single most-relevant action card for the requesting user.
GET /engagement/building-pulse Any authenticated user Recent building activity feed.

  "subject":      "Tap dripping in bathroom",
  "body":         "The hot water tap in unit 12 bathroom has been dripping for 3 days ...",
  "attachments":  []                        // optional — list of URLs
}

PUT /workflow-requests/{id}/status — WorkflowRequestStatusUpdate

{
  "status":           "in_progress",        // required — see status enum below
  "resolution_notes": "Plumber booked for 24 April.",  // optional
  "assigned_to":      "user-abc-001"        // optional — user ID of assignee
}

Status Enum

Value Set by Description
auto_resolved System Answered instantly by the classification engine. Terminal state.
awaiting_review System (on creation) Pending initial staff triage. SLA clock running.
in_progress Staff Assigned and being actively worked on.
awaiting_resident Staff Waiting for further information from the resident.
closed Staff Fully resolved and archived. Terminal state.
Overdue is not a stored status. sla_breached: true is a boolean flag set when sla_due_at < now and the request is not in a terminal state. The triage endpoint computes it at query time; it is not written back to the document.

Classification Engine

Implemented in backend/services/comms_intake_service.py::process_inbound().

Keyword patterns are evaluated in order; the first match with confidence ≥ threshold wins. The raw subject + body text is lowercased and matched via re.search().

Category Trigger keywords (examples) Confidence SLA hours Auto-resolvable
maintenance_request leak, tap, drip, pipe, lift, elevator 0.85–0.90 72 No
levy_query levy, levies, arrears, pay, owing, balance, invoice 0.85 4 Yes
renovation_approval renovate, alter, bathroom, kitchen, works 0.85 168 No
insurance_enquiry insurance, insur, claim, storm, fire 0.80 48 No
bylaw_query bylaw, by-law, by law 0.80 24 No
noise_complaint noise, loud, party, music, disturbance 0.80 24 No
reimbursement reimburse, expense, receipt, out of pocket 0.80 120 No
payment_plan hardship, payment plan, struggling, afford 0.85 48 No
pet_request pet, animal, dog, cat, bird, fish 0.70 120 No
record_request record, minutes, document, strata roll 0.75 72 No
general_complaint complain, complaint, dispute, unhappy 0.75 48 No
general_enquiry how do i, what is, when is, can i 0.60 24 Yes

Confidence thresholds:

  • ≥ 0.80 + auto-resolvable category → auto-resolved immediately
  • ≥ 0.70 → classified and queued
  • < 0.70 → classified, queued, and flagged needs_human_review=true
  • No match → general_enquiry fallback

Auto-Resolution Logic

When levy_query is auto-resolvable, the service calls db.units.find_one({unit_number, building_id}) and returns one of:

  • Credit: "Your levy account for unit {N} is in credit by ${amount}."
  • Owing: "Your account has an outstanding balance of ${amount}. You can pay at /financials/levy-payments."
  • Zero: "Your levy account is up to date. No amount owing."

Activity Timeline (Audit Logs)

Every status change writes an entry to db.audit_logs:

{
  "resource_type": "workflow_request",
  "resource_id":   "{request_id}",
  "action":        "status_changed",
  "actor":         "{user_display_name}",
  "building_id":   "{building_id}",
  "details": {
    "new_status":  "in_progress",
    "note":        "Plumber booked for 24 April."
  },
  "created_at":    "2026-04-21T11:30:00+00:00"
}

The details dict is formatted by comms_intake_service._format_timeline_note() into human-readable text (confidence shown as %, booleans as Yes/No, empty lists omitted, no Python dict repr).

Notifications

Dispatched as bell notifications + email at:

  • Request created (auto-resolved): resident receives the answer immediately
  • Request created (queued): resident receives acknowledgement + SLA estimate
  • Status → in_progress: resident notified with assigned staff name
  • Status → awaiting_resident: resident prompted to respond
  • Status → closed: resident receives resolution notes

Notifications with is_test_data: true are excluded from bell counts and history via the {"is_test_data": {"$ne": true}} filter in routers/notifications.py.

Multi-Tenant Notes

  • All workflow_requests documents are scoped by building_id.
  • TenantScopedDatabase auto-injects building_id into every query.
  • Staff can only see requests for their own building; Super Admins can override via X-Building-ID header.
  • Auto-resolution reads db.units (also scoped to the building).

Performance / Test Data

Any record created by k6 or automated tests must include "is_test_data": true. Use the workflow runner helper:

await run_workflow(building_id, payload, is_test_data=True)

The triage queue, morning card, and notification endpoints all filter out test data records.

Frontend API Client

Both API groups are wrapped in frontend/src/lib/api/community-os/index.ts:

// Workflow requests
workflowRequestsApi.list(params?)          // GET /workflow-requests/
workflowRequestsApi.get(id)                // GET /workflow-requests/{id}
workflowRequestsApi.getStatus(id)          // GET /workflow-requests/{id}/status
workflowRequestsApi.create(data)           // POST /workflow-requests/
workflowRequestsApi.createSmart(data)      // POST /workflow-requests/smart
workflowRequestsApi.updateStatus(id, data) // PUT /workflow-requests/{id}/status

// Engagement
engagementApi.createSmartRequest(data)     // POST /engagement/requests/smart
engagementApi.listRequests(params?)        // GET /engagement/requests
engagementApi.getRequestStatus(id)         // GET /engagement/requests/{id}/status
engagementApi.getTriageQueue()             // GET /engagement/triage
engagementApi.getStats(days?)              // GET /engagement/stats
Never double-prefix with /api/. The api axios instance from useAuth() has baseURL = NEXT_PUBLIC_BACKEND_URL/api. Call api.get('/workflow-requests/smart'), not api.get('/api/workflow-requests/smart').
