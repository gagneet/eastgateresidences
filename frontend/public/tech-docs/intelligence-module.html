Intelligence Module — Technical Documentation

Overview

The Intelligence module provides predictive analytics derived from maintenance records, financial data, and asset registry information. It uses algorithmic scoring and ML-style heuristics to surface risks proactively.

Capital Shock Index (CSI) Calculation

The CSI for a given year is calculated as:

CSI = Year Capital Spend / Median(Historical Capital Spends)

Risk thresholds:

  • CSI < 1.5 → Low (normal spending year)
  • 1.5 ≤ CSI < 2.5 → Major (significant capital year, plan ahead)
  • CSI ≥ 2.5 → Severe (reserve likely insufficient without special levy)

Sinking Fund Adequacy Ratio (SFAR)

SFAR = (Current Reserve + PV Future Levies) / PV Planned Capital Works

Status labels:

  • SFAR ≥ 1.25 → Well Funded
  • 1.0 ≤ SFAR < 1.25 → Adequate
  • 0.75 ≤ SFAR < 1.0 → At Risk
  • SFAR < 0.75 → Critical

Number Formatting Standards

All pages in the intelligence module enforce:

  • Currency: exactly 2 decimal places using fmtAUD() or formatCurrency()
  • Index/ratio values: up to 2 decimal places using formatNumber(value, 2)
  • Chart Y-axis labels: compact thousands format (e.g., $250k) using (v/1000).toFixed(0)k

Previously the hub page used .toLocaleString() which produced inconsistent decimal places. All occurrences have been replaced with fmtAUD().

IntelligenceAssetsPage.jsx previously defined a local fmtCurrency helper. It has been removed; the page now imports and uses fmtAUD from @/lib/utils for full consistency.

Digital Twin Architecture page (settings/digital-twin/page.tsx) previously used toLocaleString(undefined, ...) for the asset replacement-cost column, which caused browser-locale-dependent formatting. It now uses fmtAUD() from @/lib/utils.

Global Building Risk Index (Session 66)

Extends the intelligence platform with a composite 0–100 risk score per building. A higher score means MORE risk.

Risk Formula

risk_score =
  0.25 × asset_health_component          (inverted: 100 − avg_health_score)
+ 0.20 × financial_stability_component   (from financial_forecasts.risk_score)
+ 0.20 × reserve_adequacy_component      (from RAR = sinking_balance / 10yr_forecast)
+ 0.20 × capital_shock_risk_component    (from capital_shock_risks.risk_level)
+ 0.15 × maintenance_risk_component      (from maintenance_forecasts.risk_score)

Risk Level Thresholds

Score Level Meaning
0–24 LOW Stable building, no immediate concerns
25–49 MODERATE Some areas to monitor
50–74 HIGH Requires attention and action plan
75–100 CRITICAL Urgent intervention required

Reserve Adequacy Ratio (RAR)

RAR Score Status
≥ 0.70 5 Very low risk
0.40–0.69 35 Moderate
0.20–0.39 60 Elevated
< 0.20 85 High risk

API Endpoints

Method Path Auth Description
GET /api/intelligence/risk-index Bearer (owner → super_admin) Full risk score with components
POST /api/intelligence/risk-index/refresh admin only Force recompute + audit log
GET /api/intelligence/risk-index/public/{slug} None (public) PII-free public building report

Collections Read

  • asset_health_scores — per-asset health_score (0–100)
  • financial_forecasts — risk_score or risk_level field
  • sinking_fund_plan — reserve_balance + ten_year_forecast (RAR primary path)
  • annual_levies + capital_shock_risks — RAR fallback path
  • capital_shock_risks — risk_level (critical/high/medium/low) or capital_shock_index
  • maintenance_forecasts — risk_score or risk_level field
  • capital_replacement_schedule — predicted major repairs (≥$50k, within 5 years)
  • buildings — building name, address, slug for display

Default Fallback Behaviour

All components default to 50.0 when their source collection is empty. This ensures the endpoint always returns a valid response on a fresh installation. Run scripts/db/seed_risk_index_demo.py to populate demo data.
